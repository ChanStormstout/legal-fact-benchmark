# V20.5 非空证据与对象绑定修复

独立版本已实现并完成缓存和原处理入口验收，没有启动真实模型重跑。
原批次仍暂停，主线程的当前研究入口保持原样。

生成时保留 V20.4 的实际局部编号限制，另拦截空白来源选项和明确类型冲突。
原文、原来源编号和完整输入仍保留；对象身份不靠合法编号认证。

## 验收结果

97 项相关工程测试通过。包括空白来源、必需引文定位失败、
明确类型冲突、同类对象尚未核对、缺少对象、过期或重复核对记录、
跨分析单元编号、只有 NOT_ANALYZED 目录及独立保存失败答案。
完整来源尾部与旧提示词逐字相同，原 SRC 编号没有重排。

22 份完整真实缓存的数据值和数组顺序全部保留：21 份存在非法引用、
空白来源或类型冲突，被新入口拒绝；1 份全部为 NOT_ANALYZED，
明确报告 NO_ANALYZED_UNITS。这些缓存没有被修成新正确答案。
569555/P01 的 V20.4 缓存中，重建的实际引用集合含 20 个空白来源，
另检查到用途和判断各一处把 PROPERTY 角色指向 PERSON。
次承租人绑定到类型未明确的房产对象等情况保留为待来源核对，
没有通过改编号或猜测身份使它通过。

两个有实际内容的合成分析单元，经真实 tokenizer/约束器回放
470 tokens，正常结束符可用。带明确合成核对记录的正常样例通过了
原转换、合并和独立处理检查，恢复后的全部原数据一致。
这只验证工程的正常路径，合成核对不是实际模型或法律标注。

2,138 个旧文件哈希保持，原暂停记录保持。没有模型调用、模型权重加载、
训练、真实法律准确性评价、提交或推送。其他三个真实任务尚未用新版本
重新生成，不能把这次缓存拒绝称为实际输出问题已经消失。

## 可用性与后续边界

技术生成、可读目录、角色来源核对和证据用途可用性分开报告。
新入口的条件计算只有在证据/类型检查通过、实际绑定完成来源核对后
才开放；类型相容仍不证明身份相同。通过原入口后还单独报告用途
是否结构无效、模型拒绝、未决或条件性可用。

四项完整输入和新 Schema 已准备在 preparation-02 中，未获准自动生成。
下一次实际重跑应读取该目录的对应版本，并经过新 accept_saved 入口；
不能恢复旧队列或跳过绑定核对，把“OK”继续当作全部用途有效。

最终验收使用 engineering/validation-04。第一轮缓存验收中发现调用
原入口时只传了任务编号、缺少完整任务信息，该验收记录保留为初始诊断，
不作为最终依据。最终脚本读取原冻结协议的完整任务条目，并对
“没有已分析单元”增加独立状态和回归检查。
