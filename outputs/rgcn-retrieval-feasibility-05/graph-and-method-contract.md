# 最小关系图与排序接口

本轮实现一般关系图接口，没有把三个历史pattern变成排序特征，也没有验证自动发现pattern的贡献。103193047是旧图表示演示，非六案检索训练/评价输入。

## 真实例子

`case103193047 → has_assertion → a(租赁身份)`；断言通过带角色名称的边连接Nazim对象与租赁店铺；`Nazim/o2 → member_of → 八名租户/o6`。出处p0002.s001说明eight tenants included the present respondent。该案事实提议的NARRATED状态、原审/执行阶段、肯否和未决字段随节点保存，不能升级为最高法院最终采纳。

`o4(一间店铺) → part_of → o3(八间店铺集合)`没有进入确定边：原记录UNRESOLVED，因为集合不一定是一个物理整体。完整未知记录留在pending。同角色对象不合并，同段落不等于同事件，不自动计算传递闭包，不从群体继承行为。

这个案适用Kerala s11；当前六案为Delhi14(1)(b)。因此示例没有连到Delhi法源来暗示适用，也没有生成法律检索分数。其旧原文含完整裁判、未做目标答案隔离，是第二个不能用于本次正式排序的原因。

## 字段与来源

| 节点/边 | 来自哪里 | 在新案获取方式及限制 |
|---|---|---|
| case、assertion、object | 既有模型抽取，原文引文 | 按固定抽取接口从允许来源生成；本轮六案未完成这一步，不能以参考答案代替 |
| has_assertion、has_object | 确定性归档关系 | 表示这条提议属于这个案件，不表示事实成立 |
| role | 模型角色提议及对应引文 | tenant/landlord等角色名称构成不同消息类型；ID仅本案内寻址 |
| statement_status、stage | 模型标记 | 状态/阶段只作为提议保存，不因字符串定位成功得到语义认证 |
| member_of、part_of | 旧模型来源复核关系 | 仅SUPPORTED且证据在允许源；未知单存，方向和阶段保留 |
| authority、depends_on | 现有法源原文和依赖元数据 | 文本、范围、版本不变；依赖是材料恢复要求，不是适用标签 |
| has_condition、candidate_alignment | 接口保留，本轮真实图未生成 | 必须以固定、对新案可执行且不见答案的方法建立；候选对齐不等于满足法律条件 |

实体和断言节点均命名空间隔离。源证据核对仅证明引文在允许材料里，不证明状态及语义正确。实际图构造只读取显式字段；labels-audit-only、参考和旧答案不作为输入。图不能包含正确法源边。训练/检查案件不共享case/object节点或监督边；法源文本共享可以，标签传播不可以。检查时未知关系类型拒绝计算，不静默丢弃。

## 三个对照的接口

A沿用保存的原文BM25排序；原始分数与rank保留。B使用同一图上的候选对齐条件数量作为透明得分，原BM25打破平局；条件/范围/反对性质需由共同接口编码，不能专门给C更多信息。B接口当前遇到缺对齐明确NOT_READY，不用法名匹配冒充事实关系。

C是两层16维R-GCN：每种关系及其反向各有矩阵，按目标节点/关系归一化邻居消息，另有self变换与ReLU，案件—法源双线性打分。固定节点类型及文本的signed token hash是可执行的简陋特征，不称为语义embedding；ID不输入可训练嵌入。使用现有MLX，不依赖PyTorch/PyG。不选择预训练迁移路线，因此没有下载或对未核验权重作可用性承诺。

训练接口只接受有明确审阅依据的同案偏好，损失softplus(s(other)-s(preferred))，不把未标注候选负采样。候选配置固定seed20261004、Adam0.001、至多100步、300秒、图至多512节点。当前未启动真实训练，接口的拟合路径尚无真实数据验证；本轮只测试了数值前向/梯度和关闭门禁。没有宣称这一小配置是法律领域最佳模型。

缺少偏好并不证明正例—未标记学习在理论上不可行；但引入它需要选择标注机制/类别先验或其他可检验假设，现参考是选择性来源审阅而非随机标注。这轮没有这些依据，不临时新增一套学习架构。

## 排名到材料

三法共用原select：14个候选单元、已声明依赖闭包、强制基础条款、20000字符、固定库顺序；按实际JSON载荷计数。全部库载荷79451字符。预算包含来源/版本/限制包装，是实际输入限制，不仅法条正文限制；本轮不精简包装以人为腾空间。

排序器可以改变谁先占预算，但不能保证逐单元分数贪心选择最大化整包用途。共同依赖重复恢复只计算一次；大依赖包会整个跳过；选入一项可能挤掉反对/例外。接口不宣称优化了这些集合效应。六案基线重放只是确认输入转换不变，B/C未运行，因此没有“新排名提高”和“新材料收益”。

## 启动条件与划分

现成训练集为空，不是人为要求至少某个N。现六案均只列为开发诊断；后10案虽历史名称含new，已经过调试且标签任务不同，不包装为独立法源检查集。case-pools.json列出5/20/10/3案ID；availability.json列出六案及已知关联，不能相加当独立案件总数。

最低语义启动条件：同一目标上的允许事实/条件图；有依据的相对偏好或明确可比的分级用途目标；训练和检查纠纷分组可隔离；未知不当否定；至少能比较图信息相同的B/C。即便满足这些条件的小试仍只支持开发判断，不能因跑通就声称泛化。当前停止在接口和数据清单。

## 当前接口的解释边界

两层消息传递与固定文本哈希只是小型候选实现；尚未证明其能区分所需的多跳对象绑定或保留每个状态的影响。神经消息传递不执行AND/OR法律逻辑，也不能从注意力或分数产生法律证明。没有对应训练图之前，不调层数补性能。B的条件数量也不等于法律效用，可能偏好多条件法源；必须在同图上检验，当前不把该候选实现称为强基线已验证。

Pro讨论后的代码核对见[独立核对](pro-independent-check.txt)。特别注意：状态/阶段共用节点可能引入与任务无关的传播；对象关系的stage_scope等边元数据虽保存在文件，并未由adjacency数值编码；unresolved也不直接进入features。后续启动必须核验这些限定及关键关系的可达性，不能把“已保存”写成“模型已经使用”。B的条件计数不是需求覆盖；建议改法未在本轮实施。冻结版本保持不变。
