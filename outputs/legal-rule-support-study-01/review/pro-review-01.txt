第一块：整体判断
1. 现在最主要的瓶颈是实验对象没有稳定下来

我的整体结论是：

项目值得继续，但下一阶段应收敛为一个有明确范围的“法源检索与来源忠实的争点分析”研究。现有证据尚不支持自动发现法律规则、结构化推理整体优于直接回答，或完整法律裁判能力的主张。

截至这个提交，已经有价值的证据主要回答了三类问题：某个生成接口为什么失败；额外提供相关法源能否改善旧案的部分分析；某种检索融合如何改变最终送达的材料。它们尚未连接成一个充分受控的端到端方法比较。V21、V22没有最终回答实验，V23只完成了 S01 描述生成，统一索引、最终比较冻结和四份回答都尚未完成。

具体而言，你们同时受到三种瓶颈限制：

第一，研究主张与实际处理有错位。 原先关注事实关系、模式和规则发现，当前路径主要进行法源表述加工、检索和原文恢复。这个转变可以接受，但成果名称和实验必须随之改变。

第二，信息供给机制与法律分析能力尚未被分开。 一份回答没有处理某条规则，可能源于原文库根本没有、检索没有命中、预算没有送入，或模型看到了却没有正确使用。当前版本已经能记录部分链路，但很多总体评价仍把这些原因压在一起。

第三，研究决策的单位太小。 多轮旧案开发证明了若干局部问题，却没有积累足够多的固定方法配对。继续逐案改提示、再跑两次、再写一个版本报告，预期信息增益已经很低。

2. 建议固定的一句话研究问题

在给定同一案件争点、共同基础法条、法源库、展示预算和回答器的条件下，保留法律条件、适用范围及来源地位的检索描述，能否比原文检索和普通摘要检索，更稳定地送达重要法源，并改善最终争点分析的来源忠实性与完整性？

这个问题可以被否证：法律描述可能不如普通摘要，检索改善可能不传递到回答，或者三者差异小到不足以抵偿制作描述的成本。

2. 四条最有决定意义的运行链
链一：约束故障——已经可以停止猜测的部分

这一链条是本仓库目前最强的因果证据：

相同 prompt、schema、模型及采样 → 旧 mask 拒绝合法 token → 输出进入重复 → 修复该限制 → 与无约束生成得到相同完整输出

实际回放还核对了流式文本与 token 解码的一致性，因此该例没有支持“流式结果重复追加”的解释。修复代码处理的是旧快速路径漏掉的合法复合结束 token，没有把合法 JSON 条件整体撤掉。

研究教训：在讨论模型能力之前，先证明接口允许它表达正确答案。 这个教训可以形成有价值的工程案例，但不应继续占用主研究的大量生成预算。

链二：69305——有原文，模型仍然反写

实际允许输入和 B-C prompt 保留了以下区别：房东认为条款不可看；下级法院认为条款可采、租户有权依赖，但仍因转租认定作出腾退处理。B-C回答把前两者混合，最终写成法院认为条款不可采。

这条链说明两个问题。

第一，UNKNOWN 的最终标签无法掩盖解释错误。第二，即使前置材料明确标注“模型提议、未验证”，最终模型仍可能将检查信号与原文法律地位混淆。V11隔离的是加入整个程序检查块后的变化，无法进一步确定究竟是检查语义、长度、位置还是权威感在起作用。

我的决策是：当前先移除这个强制前置块。 当一个组件尚未显示稳定收益，且主研究已转向检索时，没有必要先花数轮实验把它的所有失败机制完全拆开。

链三：1033921——真正的法源缺口与已给信息遗漏同时存在

这案有两件事必须同时保留。

一方面，允许输入没有提供完整操作性银行合并方案，因此对该方案究竟产生何种租赁法保护效果保留未知，有材料依据。另一方面，输入已经提供了 ARC 与 Tribunal 对同一继受的相反判断；B实际收到这些内容，却没有像 A 那样清楚保留 ARC 的本案相反认定。

因此，正确评价应当是：

B增加了有出处的法源区别，同时损失了本案一项重要的对立判断；完整方案缺口仍然存在。

这样的结果应该允许记作 MIXED。将其强行压成一个净胜负，会隐藏研究真正需要解释的取舍。

3. 当前代码还存在什么，尚未发现什么

我发现两项应修正的新路径风险，但都不能倒推为已造成历史答案错误。

配置传递风险。 retrieve_pair 使用 CONFIG 记录配置，却没有显式把其中的单元数、字符数限制传给 select_units；当前默认值恰好相同，因此已读轨迹没有由此产生偏差。以后做预算消融时，可能出现“报告的配置变了，选择器仍使用默认值”。应显式传参，并加一个非默认配置测试。

警告传递不完整。 当前最终法律载荷没有保留原单元的全部 coverage_limit 字段。范围和版本状态仍通过其他字段可见，所以不能说所有限制都被删掉；但应把“必要的法律限制”与“纯审计元数据”明确分开，前者必须随原文送达。

此外，dependency_complete: true 仅表示已声明的依赖闭包完成，不能解释成全部适用法律、历史版本和例外均已齐备。代码对此没有完成语义认证。

在所追踪的 V11、V20实际 prompt 中，我没有发现决定性原文被组装器静默漏送，也没有发现当前检索代码替模型自动决定法律胜败。没有证据把剩余语义错误普遍归因于代码。

第三块：推荐的端到端 pipeline
1. 任务先定义为“回顾性单争点分析”

建议采用以下定义：

给定从判决中重建的允许记录，包括当事人陈述、合同文本、可见证据和下级法院处理，系统使用共同法源库，就一个预先指定的法律争点形成有出处的分析；当前目标法院的最终理由和结论不作为输入。

这允许保留下级判决，也避免把任务包装成真实判前预测。当前 V20、V23已经接近这种定义，应统一贯彻。

不要按“理由段之前/之后”简单切断全文。 纯事实、完整合同、双方主张可能出现在后段。可独立分离的非结论材料应按预定标准保留；无法分离时标注风险。另一方面，不应为了让问题可回答，把目标法院对核心争点的最终规范判断重新放回输入。

3. 未知应如何表达

最终回答至少应当能区分以下四种情况，但不必新增四套复杂 JSON 树：

事实未知：允许记录无法确定某项必要事实。
法律解释或版本未知：现有来源没有解决该法律效果，或适用版本尚未确认。
检索造成的信息缺口：共同库中存在，但本次没有送达回答器。
实现不支持：某程序未实现某种检查；这不能改写为原文没有事实或法律。

尤其要区分两个命题：

“Tribunal认定X”受到原文支持。

与：

“X应当被当前目标法院最终采纳”。

前者成立，不自动解决后者。反过来，后者未决，也不应抹去前者。

现有 point/assessment 还有一处可避免的语义混用：当 point 写成“输入没有解决X”，assessment=UNRESOLVED 到底评价覆盖陈述还是底层X，容易含混。最低成本办法是让 point 直接写底层争点，例如“该继受满足条款中的让与条件”；解释里说明证据状态与缺口。无需再增加一轮事实抽取。

4. 检索预算需要怎样改

保留原文；缩小最小完整单元。

当前一整节银行法、一个长方案与判例论证单元大小悬殊。统一给它们一段描述，只统一了检索入口，没有统一送达成本。NBI方案加依赖已从原文长度上超过20,000，说明必须先做最小闭包可达性检查。

主研究建议按完整款项、完整规则段及其必要定义/例外切分。将“理解本段必需”与“可能相关的另一段”分开；后者不应全部硬绑成强制依赖。

继续使用20,000实际展示字符上限即可，不需要先发明最优背包算法。但新主研究应取消独立的八单元硬上限，避免单元切细后又被数量上限惩罚。完整审计元数据放在 sidecar；给回答器保留必要来源、法律地位、范围、日期与版本限制。所有方法使用同一种展示方式。

主比较是L对G，L对A和G对A为次比较。 这轮不同时增加强制规则卡阅读、自动改query、GNN和检查器。

2. 样本范围与数量

主范围选 Delhi第14(1)(b)的转租、让与、占有转移或同意争点，取消“必须公司合并/法定继受”的额外限制。银行特殊继受保留制度标签，不设必须凑足的比例。普通租约、其他租管法单列。

这个选择直接针对已观察到的取样困难：V16在限定未使用材料中找不到两个同类目标；V19在24个候选上限内最多找到五个范围相容候选，却设六案启动门槛。它们说明当时的候选窗口与任务限制组合不适合继续推进，不能据此证明整个领域没有足够案件。

具体方案：

最多盘点60个候选，或使用两个工作日的取源整理预算，以先到者为止；最多纳入12个未用于方法回答开发的纠纷组。 数量是预算折中，不是统计功效保证。实际不足12就按实际数量运行；不足8则明确称小型试验，不再因一个任意最低门槛把全部模型调用归零。

选取不得依据预计哪组会赢，或者能否得到确定胜败。保留完整排除记录、同纠纷关系和先前暴露。跨案引用关系不等于同一纠纷，但需要记录，并在解释相关性时保留限制。

V23的两件普通租约案保留为四次A/L开发回答，不进入主样本数，也不因这四份答案而调整主提示。

4. 评价：先定义要点，再看答案

每案在回答前固定3–5个重要分析要点，每个附来源锚点及可能的真实缺口。它们是有限证据清单，不是一份模型生成的完整标准答案，也不发给受测模型。

评价分别回答：

检索层： 重要来源是否在库、是否进入候选、是否因预算被排除、是否带回必要定义和例外。

回答层： 是否忠实保留主体、对象、方向、否定、陈述者及法院层级；是否处理实际重要的反方；是否解释法源范围与适用条件；未知是否定位正确；有无严重过度断言。

必须分别使用两个评价视角：

来源忠实性按该回答实际收到的材料评价；端到端覆盖按共同库和预定要点评价。

库里有但没有送入，是检索层缺口。不能直接把回答器“没有看到该法源”判成编造，也不能因此把系统的检索遗漏当作真实世界没有这条法律。

“净改善”建议采用保守、可重复的规则：至少一个重要要点改善，其他重要要点不退化，而且没有新增严重错误。 相反方向记退化；得失并存记 MIXED；来源或参考争议不足以裁定时记 UNJUDGEABLE。先报告分项，再汇总案例数。

匿名方法ID、平衡答案顺序能够减少部分偏差，但内容仍可能暴露方法。四次复核中至少两案预选，其余按预定严重分歧规则选择；保留相反意见和原文证据。不同会话不自动等于不同模型，更不等于独立法律真值。

没有人类gold仍可以得出局部来源反写、引文不存在、条件遗漏、排序与预算机制等结论，也可以报告有明确限制的模型辅助配对结果；不能据此宣布一般法律正确率。

5. 失败、重复与停止

只允许明确的传输中断或上传失败做一次同内容技术重试，总额最多两次。语义错误、遗漏、不满意的答案不重试。一个方法失败，不取消其他方法。预选重复不替换首次答案。

首次回答、重复回答、技术重试分别保存。以纠纷组作为分析单位，不能将grounds、查询、法源或重复次数当独立样本扩大分母。

结果的处理应提前写清：

L胜A但不胜G： 保留描述辅助检索，撤回法律专用内容已有独立增量的主张。
检索改善、最终回答未改善： 报告收益停在检索阶段；根据轨迹定位下游整合问题，不自动开启新提示轮。
三者接近或L更差： 采用更简单的方法，保留负结果。
来源复核分歧足以改变方向： 结论为不确定，停止追加裁判模型。

12个目标不足以证明跨领域稳定优势，但足以比反复两案开发更有力地决定：是否值得继续投入法律专用描述。

不足12就按实际n运行；低于8标小型试验，不再设置“少于六案所以零调用”。

共同法源库目标约20–40个完整逻辑单元，从基础法条、开发来源及同制度相邻来源构建。
不根据新目标的最终判决补正确法源。

六、评价与停止

分别追踪：
重要法源在库可用→候选排名→预算后送达→实际回答使用。

来源忠实按每份答案实际收到的材料核对；
检索及端到端覆盖按共同库和预定要点评价。
库里有但没送到不能算真实法律缺口；
不能因A未看到B-only材料直接判A产生幻觉。

每案评价：
重要要点完整性；
主体/对象/方向/否定/法院层级；
法源范围、地位及适用解释；
重要反方；
真实缺口与条件性后果；
严重过度断言和引用支持。
UNKNOWN不自动加减分；模型assessment不当评分；接口失败和法律错误分开。

净改善：
至少一个重要要点改善，其余重要要点不退化，且无新增严重错误。
反向则退化；得失并存MIXED；资料/参考争议UNJUDGEABLE。
先分项，后汇总案例；不把grounds、查询或重复调用当独立样本。

匿名方法ID并平衡答案顺序，承认内容可识别。
4次复核至少2案预选，其余按预定严重分歧规则选择。
保留相反评语及源锚点，不以模型多数票认证法律真值。
争议可能改变结论时报告保守/宽松边界，不报告一般法律正确率。

L胜A但不胜G：结论限于一般描述辅助检索。
三臂无明确差异：保留更简单方法。
检索改善但回答无改善：报告收益停在检索，定位下游问题，不自动追加修补轮。
复核分歧改变方向：报告不确定并停止。
不得为转正补案例、改题、加卡、改评价或启动下一版本。
