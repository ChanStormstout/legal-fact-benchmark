二、实施的主流程
接通以下流程，尽量复用当前接口：
来源与版本化规则 → 模型提出事实和候选用途 → 语义匹配 → 完整依赖搜索 → 独立检查 → 完整分析。
明确各组件的职责：
1. 模型提议保存事实、对象、时间、陈述状态、候选用途和出处，始终保留提议身份。
2. 语义匹配判断某条证据或证据组合，是否适合支持指定前提。它是可出错的模型判断。
3. 依赖搜索寻找完整的必要条件组合、替代路线和例外，不把末端结论与它的前置步骤拆开选择。
4. 独立检查器检查来源地址、身份绑定、规则版本和显式逻辑，不把引用有效或模型高分当作法律含义正确。
5. 最终分析区分来源记载、模型判断、程序检查结果、未覆盖的法律解释和实验性结论。
参考答案只用于训练或评价。不得在测试运行时调用参考答案，批准前提后再把结果报告为自动分析。
现有“给定审阅前提后的条件性推导”仍可保留，但必须与“从原始提议开始的自动流程”分别报告。

四、明确训练什么，避免把新标签混成旧标签
监督单位固定为：
纠纷及程序阶段 × 具体规则前提 × 对象绑定 × 证据或明确的证据组合。

例如：
“原告声称发生转租”可以用于证明“原告提出了这项主张”，不能直接用于证明“法院认定发生了转租”。
每个用途只建立粗粒度判断：
- USABLE：在指定陈述地位和范围下，可以承担这个明确用途。
- UNUSABLE：存在有来源的明确不适用原因，例如对象、日期、陈述地位或推断强度不符。
- UNRESOLVED：材料不足或存在无法解决的解释争议。
- UNLABELED：尚未评价，屏蔽损失，不当负例。
每项保留必要原文、具体用途、对象及简短理由，不增加逐词或大量pairwise微标注。
还必须区分：
- 证据与问题相关；
- 证据可用于某个前提；
- 所需前提已经成立；
- 请求的全部必要条件已经成立。
这些不能由同一个分数替代。
独立证据不足以承担整个前提时，可以标注一个真实、来源明确的证据组合。不要把所有单条证据都强行标成支持或反对。
旧法院结果、旧authority-use标签和旧完成路线标签保留原义。兼容性未确认时，不自动转换成新监督。

八、固定比较方法和实际训练方式
使用同一批案件、来源、候选用途、规则及监督，比较：
1. 条件先验：只利用TRAIN中相应前提的标签分布，检查是否只需记住常见答案。
2. 非学习基线：保留原始LLM用途判断，执行共同结构检查与完整依赖搜索。
3. Flat：读取同一批事实、前提、对象及关系信息，不进行图传播。
4. R-GCN：复用两层、64维隐藏层、4关系基的结构。
5. Cross-encoder：把“需要证明的具体前提”和“候选证据及其状态”放在一起编码，学习三类用途判断。
Cross-encoder优先采用：
Alibaba-NLP/gte-reranker-modernbert-base
该模型原始相关性分数不能直接当作法律用途正确性，需接入本轮三分类任务头并训练。
先核对模型卡、许可证、依赖、权重大小和本机运行条件。允许在项目专用环境中安装必要依赖并下载这一项模型，固定revision；不改旧MLX环境，不下载其他候选模型开展排行榜。若出现未预见的大额下载、付费服务或无法兼容的运行要求，暂停该依赖并报告，其他独立工作继续。
只做一次使用合成内容的加载、前向、反向和保存验证，不开展真实案件模型预跑。
固定训练方案：
- Cross-encoder冻结除最后两层与任务头以外的编码器参数。
- 编码器学习率 2e-5，任务头 1e-4。
- AdamW，有效batch size 16；显存不足通过梯度累积实现。
- 最多6轮，DEV连续2轮未改善停止。
- Flat／R-GCN保留现有架构，必要修改仅限用途输出接口；学习率 0.001、weight decay 0.0001、dropout 0.1，最多100轮，DEV早停10轮。
- 三个固定种子 20261001 / 20261002 / 20261003。
- 最多9次正式拟合，不扫描模型、图结构、损失函数或超参数。
- 训练总运行预算6小时；耗尽时保留完整和失败运行，不临时改变配置补跑。
三种模型使用同一监督含义。损失先按请求、再按纠纷汇总，避免一个案件生成很多记录就支配训练。未知标签屏蔽，明确未决正常训练。
长材料使用冻结的、可追溯的局部证据范围与上下文组织，不静默截断。无法在模型上下文中完整表达必要输入时记录覆盖失败。
Flat与R-GCN的比较用于判断图传播增益；Cross-encoder与它们的比较属于整套方法比较，不能把预训练和文本编码差异都归因于“有没有图”。
九、完整搜索与学习分数的连接
各方法均通过同一搜索和检查入口。
学习模型提出用途状态与分数，但不得：
- 把模型预测自动升级为审阅批准；
- 把某个候选低分解释为原文没有相应证据；
- 丢掉所有未决及反对材料后获得表面更高完成率；
- 只保留结论节点而遗漏必要前提。
在候选池很小时，完整搜索可以处理全部候选。此时若不同排序最终得到相同材料，就报告排序未改变送达结果，转而评价语义用途是否改善。
无法形式执行的法律判断可以作为明确标记的模型前提进入条件性分析；最终凭据必须显示它依赖哪些尚未独立验证的判断。
不得用程序自己生成的标签，再证明程序或模型“法律正确”。
十、冻结和评价
进行两次用途不同的冻结：
- 准备冻结：候选规则、数据划分方式、标签合同、预算和来源政策。
- 训练冻结：实际数据、输入特征、模型版本、训练配置、搜索规则和评价标准。
训练后不根据TEST结果修改方法再重跑同一批。
先评价四层：
1. 来源覆盖：必要依据是否在候选中；不在候选中时，排序器不能凭空找回。
2. 用途判断：是否把主张当认定、错接对象日期、误判推断强度；分别报告错误接受和错误拒绝。
3. 完整依赖：是否保留必要步骤、替代路线、反论和关键缺口。
4. 完整分析：结论与依据是否一致，是否新增无依据判断，是否忠实保留材料限制。
不得在评价排序时把原来漏检的正确候选偷偷补入候选池。可以另列“给定候选后的分类结果”，不能冒充端到端结果。
按纠纷汇总，报告各类错误和方法之间的配对差异，不把大量边、用途或状态当独立案件。
在DEV上确定一个学习方法用于完整回答比较，规则预先冻结：优先减少重要错误接受，其次改善已确认依据覆盖；差异无明确实质意义时优先成本低的方法。保存三个种子的全部结果，不选最好种子冒充整体。
TEST上最多比较三种完整分析：
- 直接LLM读取共同原文与规则；
- 非学习基线整理的分析＋同样原文与规则；
- DEV选定学习方法整理的分析＋同样原文与规则。
三者使用同一网页配置和最终回答合同；最多20案、60次最终回答，逐案一次，不追加纠错重答。实际测试不足20案按实际数量运行并说明局限。
如果DEV没有显示学习方法优于非学习基线的具体收益，停止新增完整回答调用，交付用途判断、搜索和成本结果，不为花完预算而继续生成。
集中审阅一次，不能只检查模型主动引用的段落。模型参考不完整时，只报告已有明确依据的覆盖，不称为完整召回率或法律准确率。
十一、工程验收和保存要求
必要测试覆盖真实入口：
- 当事人主张不能直接成为法院认定；
