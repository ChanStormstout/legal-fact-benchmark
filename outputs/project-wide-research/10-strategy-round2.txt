目前仍存在的覆盖缺口

五、最接近工作的深入比较：哪些想法已经“撞车”，哪些仍值得发展？
1. EDC：基本规范化流程已经高度接近

EDC 不是简单的 embedding clustering。它已有开放关系抽取、关系语义定义、候选检索和规范化，并讨论了自动生成 schema 的设置。它还报告了过度概括的问题，例如不同关系被压入同一类。
arXiv
+1

因此，下述贡献表述应停止使用：

“我们首次让 LLM 抽取事实，再通过定义和相似性将不同说法规范化。”

仍值得检验的差异是：法律语境中的角色、陈述状态、时间和重要限定条件，是否需要不同于通用 relation canonicalization 的判定对象与评估协议；这种区别是否能改善下游发现。

只在 EDC 外面增加几个法律字段，差异还不够。需要证明这些字段改变了哪些错误、在怎样的覆盖率和成本下产生价值。

2. LLM 发现 legal factors：不是空白，但 factor 与 canonical fact 不应混为一谈

Gray 等人的工作已经从判决分析和结论中归纳 factors，再通过人工或 LLM refinement 形成表示，并测试结果预测。其结果并不支持“自动产生一套 factor 就与专家体系等价”。
arXiv
+1

我们与它的潜在区别不是“也用 LLM 发现法律类别”，而是：

该工作研究的 factor，可能已经是经过法律解释、带有论证方向的因素；我们希望保留的原子命题，首先应能区分发生了什么、谁这样主张，以及法院是否认定。

这两层可以连接，但不宜合并。否则 canonicalization 很容易变成用法院事后理由给案件重新编码，然后再“发现”与结果有关的因素。

这里也不能反过来指责该论文使用理由就是错误：它的回顾性 factor discovery 可以合法使用这些材料；问题在于能否把相同设置解释为前瞻预测。

3. LRI：从多案例归纳规则，甚至带验证循环，都已经有人做

LRI 用一组类比判决归纳规则，2026版 SILVER 又加入对候选规则的验证和迭代。因此，“LLM 从案例总结规则，再找未覆盖案例补规则”不构成充分新增贡献。
arXiv
+1

更重要的问题是：一个能覆盖案例的归纳陈述，究竟是什么类型的规则？

“这一条件在多数获支持请求中出现”，可以是经验规律；“适用法律要求满足这一条件”，则需要法律来源、适用范围和例外支持。前者即使在保留集复现，也不自动成为后者。

因此，C 若继续推进，最有价值的差异可能是显式区分规则来源与地位，并验证适用范围、例外和反例，而不是再次做自然语言规则生成。但这仍需与 LRI、法律规则抽取及 argumentation 原文继续比较，不能现在就宣称无人研究。

4. Cequel 与 AAAI 2026：预算控制不是只属于我们的难点

Cequel 已把查询预算、文本对/三元组选择、噪声约束和聚类组合起来。它在一般文本聚类任务上的成功，不自动证明适合法律等价类，但足以否定“选择最值得问的 pair”是新的核心想法。
arXiv
+1

我们可能有价值的差异，应落在优化目标改变：

一般聚类关注类别恢复质量；法律规范化还需要考虑某次错误合并是否会改变后续模式含义。

不过，若提出“按下游危害选择专家检查”，也必须面对一个难题：怎样估计危害而不提前查看本案结果，或不断根据想得到的模式修改语义类别。这应是后续方法研究，而不是本轮直接成立的算法。

5. 不确定模式挖掘与 PPI：不能把“加置信度”当创新

不确定数据挖掘已有概率项和期望支持度；PPI 及其分层扩展已经研究利用少量人工标签纠正机器产生的总体统计偏差。
Philippe Fournier-Viger
+2

本项目特殊而值得研究的地方，可能是误差具有共同来源：

如果“未提供”被错误统一为“拒绝”，同一个错误定义可能污染多个案件中的多条事实。它不是每条事实独立地以5%的概率随机出错。

因此，合理路线不是给每个事实填一个0.95后相乘，而是研究定义层错误、实例层错误和案件层依赖如何传到模式验证。

但需要明确：**适应性选模式、同一案件家族相关、非随机专家复核和语义版本变化，都可能超出直接套用 PPI 的条件。**当前只能将其列为已有统计工具和待验证扩展方向，不能借它宣布获得了完整保证。

6. LEGIT、CourtReasoner、CaseFacts：可追溯不是证明正确

这些工作分别推动了 issue-tree rubric、分阶段论证评估、依据判例的法律命题核查，说明领域正在把“最终答案是否正确”拆成更细的验证对象。
arXiv
+2

但不能因此把一个来源链接、一个正确法条，或一个顺畅推理文本当作法律证明。

例如，LegalGraphRAG 的 “Traceable Correct” 操作化涉及正确预测和相应法条检索；这与逐条验证事实前提、规则适用、例外和推理有效性不同。
arXiv

因此，图中的 “The proof is in the trace” 应被当作需要实现并检验的设计愿景，而不是已有事实。

S 不是多加一个工程模块，而是所有后续结论成立的前提。

A 与 B 可以互相提供开发反馈，但必须设边界：如果 B 发现某类别很能区分输赢，不能据此偷偷改写“何谓等价”。可以提出新的候选分类层或假说，但应重新命名、版本化并独立验证。

C2 的外部法律规则可以从一开始帮助 A 判断重要差异。这不属于泄漏。泄漏风险主要取决于是否使用了目标案件在目标时点不可获得的结果或理由，而不是某个字段在流程图上画得靠前还是靠后。

七、四种整体架构路线的公平比较
路线一：专家规则与 factor 体系优先

先由专家定义有限的 factors、法律 criteria 和类别层级，再让 LLM 为案件标注，最后进行比较、统计或论证。

这是 CATO/IBP 和 criteria-mapping 路线的现代实现方向，不是新范式。
Springer
+1

路线二：完全自下而上的开放规范化与发现

先开放抽取，再自动规范化和形成类别，然后挖掘事实组合，最后由专家解释。

这是最贴近 PDF 的路线，也最容易发现预定义词典之外的候选结构；但它面临 EDC、factor discovery 等直接近邻。
ACL Anthology
+1

路线三：有限专家锚点＋开放类别＋独立模式验证

专家先定义适用范围、少量关键区分和评价规范，不要求完整列举所有事实类别。系统允许开放抽取和新类别，但必须保留未知信息，并在独立案件中验证模式。

这是我暂时推荐的路线，性质是“合理组合＋待验证研究假设”，不是已证明优于另外三条。

路线四：不建全局类别库，按问题局部比较案件

直接检索相关案件，由 LLM 或论证框架针对当前问题比较事实、寻找反例、输出候选规则；可以采用 query-local 的 factor mapping，而不先规范化整个语料库。

非全量 factorization 的 AAM-CBR，以及直接多案例规则归纳，说明这一替代路线不能忽略。
arXiv
+1

为什么暂选路线三？

不是因为“混合系统通常更好”，而是它最容易设计一个真正能够否定自己的实验：

在相同专家时间和模型预算下，它是否比专家体系、开放规范化和查询局部比较，产生更多经过复核、在独立案件中成立的有效发现？

若不能，应该选择更简单的路线，而不是给混合系统继续加 agent。

八、暂定路线中，A、B、C 各有哪些候选算法家族？

以下所有组合均为研究建议；“为什么可能有效”不是已经取得的实验结果。

A：可靠、可复用的表示
路线	算法家族	为什么可能有效	失败边界
固定 schema 标注【已有方法】	专家 factor 表、结构化信息抽取、规则约束标注	减少开放类别歧义，便于建立 gold	schema 不完整或粒度错误会限制全部结果

暂定选型：第三条，但必须与第一、第二、第四条同时比较。

表示层还应分开两个对象：

实例层保留原始主体、事件、时间、出处和陈述状态；类别层规定哪些维度被抽象、哪些差异必须保留。

同一个 canonical predicate 可以出现在“当事人主张”和“法院认定”的不同实例中，但这不意味着两条实例记录可以互相替代。是否允许它们进入同一种 cluster，取决于 cluster 表示的是动作类别还是完整命题等价；必须先定义，而不是交给聚类结果反向决定。

**关键否决条件：**在匹配覆盖率和成本后，新增结构不能降低法律重要误合并；或者合法同义事实大量被 context blocking 漏掉。此时不能只报告高 merge precision。

暂定顺序：先闭合项集和紧凑模式集，再对比模式；只有证据表明关系绑定重要，才增加图/ILP。

为什么不一开始选 gSpan？因为目前还没有证明可靠的图边已经存在。如果主体绑定、时间关系和因果指向仍靠未经验证的 LLM 补出，复杂模式只会把错误包装得更像知识。

一个需要测试的例子是：

“某主体提出请求，另一个主体拒绝了该请求”，与“某主体提出请求，同时案件中有人拒绝了另一个请求”，具有相同的词袋或粗粒度事实集合，但不是同一关系模式。

这可以成为图路线的优势测试，但必须用真实原文和专家核验，而不是只在人工构造例子上证明算法当然能处理变量绑定。

当前最重要的接口不是 JSON 字段数量，而是模块之间到底承诺了什么。

其中 witness 指“某案件为什么被判定符合该模式的具体实例与原文支持”。

可以用下面的总体协议开始实现：

Plain text
1. 确定领域、程序阶段、时间范围和运行模式。
2. 按案件家族划分开发、验证、最终测试材料。
3. 建立允许输入清单；隔离结果与不允许使用的理由。
4. 抽取有出处的命题，保留未知和陈述状态。
5. 用候选表示路线建立类别；在开发材料上检查和修订。
6. 冻结类别语义、映射程序、规则背景和版本。
7. 在发现材料上产生候选模式，不把候选当作结论。
8. 在独立材料上重找 witness、反例，并进行语义和统计检验。
9. 输出模式档案；有条件地接入比较分析或理由重建。
10. 发现语义错误后形成新版本；不得追改测试标准后继续沿用旧测试结论。

这里的关键不是“十步流水线”，而是发现与确认分开，原文与派生表示分开，语义修订与测试结论分开。

十、关键实验：怎样证明这项研究真的有价值？
1. 主实验不应该只比较聚类准确率

我建议设置三个层次，但用一个端到端目标统领：

单位专家时间和模型预算内，系统能产生多少经过独立复核、对案件比较有帮助的非冗余发现？

实验层	主要观察	为什么需要
表示质量	错误合并、遗漏合并、未知处理、定义稳定性、候选召回	判断上游是否可靠
发现质量	模式原文成立率、独立案件复现、反例覆盖、冗余、统计不确定性	判断“发现”是否真实
实际比较任务	关键事实差异与遗漏识别、支持/反对案例覆盖、专家完成时间	判断系统是否有实际研究价值

第三层尤其重要。否则项目可能做出一个统计上谨慎的模式列表，却没有证明它能帮助任何人理解案件。

可以设计的有限终端任务是：给定一个争点和一组案件，系统生成比较分析，指出共同结构、可能改变法律分析的差异，以及不能被当前模式解释的案例。专家评价的不只是“文字是否流畅”，而是这些差异是否真实、重要、有出处，并比较完成时间。

这不是全新的法律任务——案例比较传统早已有之。潜在贡献是证明某种表示与验证机制，是否让这一任务更可靠或更省专家劳动。
Springer
+1

2. 强基线必须跨越三种假设

**表示层基线：**原文直接比较、仅做有依据的角色替换、embedding 聚类、EDC 式规范化、预算匹配的约束聚类、专家 factor 表。全单例可以作退化检查，但不能当作有竞争力的最终方案。

**发现层基线：**同一表示下比较闭合项集、MDL 模式集、受约束对比模式；同一挖掘器下比较不同表示。否则无法知道收益来自规范化还是更强的搜索器。

**端到端基线：**直接多案例 LLM、检索增强比较、专家 schema 系统，以及不构建全局类别库的局部比较方案。

这里应有一个重要的交叉实验：

先在人工校验表示上比较挖掘方法，再在固定挖掘方法下比较自动表示。

这可以避免所有模块一起变化，最后只能说“整套系统有一点提升”。

3. 公平预算要算总成本

不能只匹配 LLM 调用次数。三元组查询和两两查询的输入长度不同；一个方法可能额外得到专家定义、目标法条或长篇理由。

至少记录：模型与版本、输入/输出 token、检索成本、调参预算、运行时间、专家分钟数，以及预先构建 ontology 的成本。

专家定义的前期投入可以按多次任务复用摊销，但不能不计成本。路线四的局部比较也应按重复查询次数评估，不能只测一次就断言不需要共享表示。

4. 数据划分与泄漏控制

建议首先按同一诉讼及其上诉、关联裁判或高度重复材料形成案件家族，再划分。仅凭不同 doc_id 不能推断独立性。

之后分别测试时间、法院或法律背景的迁移。若测试新案件的归纳泛化，不能先在全部测试文本上学习类别定义；新类别应允许以 unknown/open-set 方式出现。若选择 transductive 设置，即允许利用未标注测试文本，必须明确命名，不能混报为纯归纳结果。

还应处理两个容易遗漏的问题：

**第一，发现集和测试集分开后，测试很多模式仍然存在多重检验。**保留集不是自动免除统计校正的许可证。
Springer

**第二，公开判决的选择与记载方式可能并非随机。**即使机器标注误差被专家校正，也不能自动把“判决中记载某事实的频率”解释为“全部现实案件中该事实的频率”。PPI 类方法不能凭空恢复没有进入样本总体的信息。
arXiv

LLM 预训练记忆也无法靠删掉案件名就彻底排除。可以做案件名遮蔽、事实变化测试和较新案件测试，并披露模型时间信息，但不能宣称完全消除记忆影响。

5. 专家标注：不仅是两事实等价 gold

最少需要四类专家任务：命题与角色是否有原文支持；等价/粒度与重要差异；模式 witness 和反例；比较分析是否有法律研究价值。

专家还应参与定义 materiality，即哪些差异在该研究语境下具有法律重要性。这不应完全由机器根据自己的后续分类效果决定。

应把两类样本分开：

随机或有明确抽样权重的审计样本用于估计总体错误；主动挑选的困难样本用于改进方法。只标最难样本或只标最高置信样本，都不能直接用于无偏报告整体质量。
