==================================================
六、四类 coarse authority-use 的冻结判准
==================================================

本轮继续只使用：

CORE
BACKGROUND
IRRELEVANT
UNKNOWN

不要新增训练类别。

判断对象是：

“给定固定 research question、允许来源、程序阶段和法源范围，
这个 authority unit 对当前分析承担什么作用？”

每个非 UNKNOWN 标签必须能够回答三件事：

1. 当前案哪个具体分析问题需要它？
2. authority 提供什么法律命题？
3. 该命题如何帮助分析这个问题？

仅以下理由不够：
- 同一法典；
- 同一法律体系；
- 同样出现 subletting；
- 将来理论上可能涉及；
- 没有任何对应事实但“作为背景可能有帮助”。

具体定义：

CORE
----
该 authority 提供当前一个重要问题所需要的：
- governing rule；
- legal test；
- element definition；
- burden / evidentiary standard；
- material limitation；
- exception；
- important counter-rule / counterargument。

如果忽略该法源所提供的法律命题，
当前分析会出现实质缺口。

CORE 不表示：
- 支持某一方；
- 事实条件已经满足；
- 最终结论确定。

BACKGROUND
----------
对当前具体问题有可说明的辅助作用，例如：
- 解释一个已相关 CORE rule 的上下文；
- 限定当前确实使用的 analogy；
- 提供非决定性的佐证；
- 帮助理解某个已实际出现的法律分支。

必须说明：
“它具体辅助哪一项当前分析”。

仅“同一体系”“同一主题”“可能以后有用”不能成为 BACKGROUND。

IRRELEVANT
----------
根据当前固定问题和允许来源，
可以有依据地判断该 authority unit 不承担上述作用。

例如：
- 处理的是另一个法律机制；
- 当前问题明确不涉及该程序；
- jurisdiction / statutory mechanism 与本案明确不匹配；
- 且不存在需要回应的对应主张或限制。

以下情况本身不自动等于 IRRELEVANT：
- 没有引用；
- 某条件未满足；
- 来源没有提到某事实。

UNKNOWN
-------
当前材料不足以可靠确定 authority use，
或者用途边界存在无法通过现有来源解决的分歧。

“rule condition 是否满足未知”
与
“rule 对本案是否有用未知”
必须分开。

技术引文定位失败继续使用 ISOLATED 等状态，
不能伪装成 IRRELEVANT。

重要 counter-rule / distinguished precedent 可能是 CORE；
不能因为它反对主要论点就标 IRRELEVANT。

两个 authority 若都可以充分提供同一个重要规则，
可以都是 CORE candidate；
不要为了人为制造唯一最佳 authority 把其中一个降为 BACKGROUND。
但 downstream 评价时不能把重复法源机械当成两个独立不可替代贡献。

七、数据处理必须分成两个互相隔离的路径
==================================================

为了避免 graph 和 label 互相证明：

A. L-path：authority-use review
--------------------------------
输入只能包含：
- case_id；
- 原始固定 research question；
- 程序阶段；
- 完整 allowed source；
- 本轮4项 authority 原文及必要 dependencies；
- 当前已有 use label / reason，仅作为待复核旧记录。

不得提供：
- S/B/C 排名；
- selection results；
- graph alignment；
- graph review结果；
- DEV指标；
- 哪种标签会帮助哪个模型。

输出对每个位置：
- KEEP；
- CHANGE（CORE/BACKGROUND/IRRELEVANT）；
- UNKNOWN；
- ISOLATE；
以及简短 source-grounded reason 和 case refs。

B. G-path：graph / alignment review
-----------------------------------
必须是独立新对话／独立High任务。

输入只能包含：
- 同一个原始 research question；
- allowed source；
- 4项 authority 的 conditions；
- 当前 case graph 中与4项相关的 need / fact / relation /
  condition / alignment proposal。

不得提供：
- authority-use label；
- L-path结果；
- S/B/C排名；
- selection metrics。

只判断：
- scope compatibility；
- need 是否真的由固定问题／来源支持；
- condition alignment 是否有实际来源桥梁；
- candidate / uncertain / incompatible 是否合理；
- 是否存在模型自行扩展出来、但原问题并不要求的旁支。

不能：
- 因 label=IRRELEVANT 就删 graph；
- 因 graph scope=DIRECT 就证明 label=BACKGROUND；
- 为了图和标签一致而互相修。

十三、预先固定投入决定
==================================================

训练前把以下规则写入protocol：

A. B相对S
-----------

只有当：
- 两个预定seed均出现同向或至少不冲突的
  case-conditioned material-selection improvement；
- 收益出现在不止一个DEV case；
- 没有以丢失重要CORE/counter-rule换取表面计数；

才认为：
“simple case-conditioned ranking 显示值得继续的开发信号”。

如果：
S≈B，
或者B主要只是不可确认优劣的material swap，
优先保留更简单的S。

B. C相对B
-----------

只有当：
- 两个seed都出现可解释增益；
- 跨多个案件；
- 不是只靠一个seed；
- 没有同等严重的重要材料损失；

才保留当前R-GCN作为候选。

如果：
C一个seed明显好、另一个明显差，
结论 = unstable，
暂停扩大GNN。

如果：
B>S，但C≈B，
结论 =
case information useful,
graph neural message passing not yet justified。

如果：
S≈B≈C，
结论 =
当前任务/监督没有证明case-conditioned ranking净价值，
本阶段结束。

注意：
C相对B的收益不能严格归因于message passing，
因为C同时增加text encoder/nonlinearity/graph propagation。
本轮不新增C0去分解。
