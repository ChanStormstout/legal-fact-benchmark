# Legal AI: From Literature Mechanisms to Algorithm Redesign

September 29, 2026. Research design only: not trained, run or proven superior to v2 on project data. It replaces v2's default recommendations while retaining source provenance, instance identity, status, exact binding and reasoning semantics. The earlier slides were not synchronized to this version. This is a historical proposal, not execution authorization.

## 1. Changes

The recommended route learns bounded fact definitions, proposes executable relational concepts from cases, uses sources/matches/difficult instances for local repair, and connects reviewed legal conditions to those facts.

| Module | v2 | This version |
|---|---|---|
| A: representation/categories | All-member EQ graph and integer-programmed strict clusters | Versioned definition-driven mapping; pair judgments diagnose and prioritize review rather than becoming inviolable semantic truth. Strict equivalence uses full canonical signatures separately. |
| B: relational discovery | Enumerate short conjunctions in a fixed vocabulary, then compress/select | Real-instance generalization, LLM concepts and bounded program edits generate candidates; execution and sourced counterexamples drive repair. Compression no longer decides legal usefulness. |
| C: legal connection | Joint rule acquisition/review with detailed downstream argumentation | More explicit acquisition, scope, factual-to-legal bridges and translation tests; established argument semantics remain. |

Publication year does not determine adoption. Recent mechanisms are transferable proposals, not demonstrated local winners. v2 already included joint rule generation and expert review; C refines candidate repair and acceptance rather than inventing that step.

## 2. Shared Objects

Preserve four layers: source assertions with speaker, contract/request/event, polarity, dates, status and location; base fact types with explicit meanings and slots; derived descriptive relations computed from facts and reviewed operators with input/binding traces; and legally grounded factors or conditions such as valid notice or material breach. Recurrence cannot turn the fourth layer into legal truth.

A cluster of type instances permits different parameters. A strict-equivalence cluster requires identical full signatures under a declared abstraction policy. Families organize supported parent/related types without authorizing merges. Cross-case equivalence means the same structure at a specified comparison level, never the same real event. IDs remain separate. Signatures may replace names with role variables but preserve argument relationships and protected distinctions. Within a case, use real object IDs rather than BUYER as identity. Few repeated strict signatures containing all amounts do not prevent B from explicitly generalizing amounts as variables.

One buyer can have different relations under K1 and K2, so identity and contract bindings both remain. ALLEGED and FOUND are distinct; unmentioned, unproved and explicitly negated are different states.

All execution uses a bounded typed query language. LLMs produce ASTs compiled locally, not arbitrary Python/Prolog. Permit indexed joins, explicit-negative lookup, registered numerical/date comparisons and aggregations. Prohibit files, networks, arbitrary recursion and negation inferred from missing data.

## 3. A: Fixed Definitions and Targeted Revision

### Interface and initialization

Input: contextual assertions plus an extensible versioned registry. Output: base instances, memberships, retained parameters, pending memberships, revisions and source evidence. Never overwrite sources or versions. Cards contain ID, meaning, typed slots, protected qualifications, exclusions, reviewed aliases, positives, difficult negatives, context and version; no outcomes.

Start with open extraction in one defined legal problem. Retrieve similar assertions by action/relation and argument types only as material for drafting. The LLM drafts cards from a small source group, then tests the nearest materially different examples. Initial definitions require source review. Unreviewed cards may run as marked research candidates but cannot be pooled with reviewed definitions. Atomic splitting preserves quantifiers, conditions, shared events and negation scope; nobody paid does not justify unsupported individual negatives.

Map only after establishing a fixed version. New expressions first extend aliases/parameters; create a new type only if needed. Do not create a class for every wording or erase distinctions to reduce class count.

### Mapping and review algorithm

1. Extract with source anchors, role evidence and identity, checking each field. Edits are KEEP, FIX, meaning-preserving REWRITE, or EXCLUDE from the computational view while preserving the record. Record changes and sources. Insufficient information is UNKNOWN, not automatic deletion. One automatic repair per item; persistent failures await review. Do not broaden definitions to conceal extraction errors. GraphRefine motivates operation separation, not a claim to its supervised performance.
2. Retrieve the union of exact aliases, BM25 and vectors, initially at most 20 cards per instance. Similarity ranks; unknown context is not a hard exclusion.
3. Map source components to card slots with sourced support/conflict/unknown per slot. Polarity, direction, party or scope conflict blocks mapping rather than being offset by a total score.
4. Retain meaningful modifiers outside required slots. Strict equivalence requires full abstracted signatures to match: PAYMENT membership does not make partial/full payment interchangeable. Unstructured qualifications remain in source text and keep strict equivalence pending.
5. Accept a uniquely eligible leaf definition as a machine mapping. If parent and child both apply, choose the most specific fully supported child and retain the parent relation. Two passing cards without reviewed inclusion remain ambiguous, not distance-selected. No suitable card triggers a candidate card.
6. Initially spend one quarter of review budget B on fixed random sampling and three quarters on conflicts with reviewed distinctions, dual membership, difficult-member inconsistency and new expressions/parameter combinations, in that order. Within tiers rank affected dispute families, then diversify expressions. These ratios are implementation defaults, not proven optimal.
7. Permit only evidenced slot/status corrections, aliases, mandatory parameters for omitted qualifications, sourced splits and bidirectionally reviewed merges without protected distinctions. Broadening merely to fit members is disallowed.
8. Accept a version only after replaying applicable reviewed positives/negatives, correcting at least one confirmed error and introducing no regression. Prefer the smallest passing change. Mean confidence is not acceptance evidence. Remap all dependent instances before release.

```text
for assertion in source_assertions:
    cards = retrieve(assertion, registry)
    mappings = check_slots_qualifiers_and_exclusions(assertion, cards)
    commit_unique_compatible_mapping_or_keep_pending(mappings)
while review_budget_remains:
    item = next_conflict_boundary_or_random_audit()
    evidence = review_original_text(item)
    if evidence does not resolve the issue: keep_pending(); continue
    patches = allowed_local_edits(item, evidence)
    accept smallest patch that fixes an adjudicated error
        and passes every applicable reviewed regression case
    recompute dependent mappings and strict signatures
freeze_registry_version()
```

### Rationale relative to v2

The v2 example has EQ edges ab, ac and bd and chooses two for objective gain. Genuine equivalence is transitive; such a graph first signals judgment/context inconsistency. Retaining an extra EQ edge does not prove a better legal category.

Shared definitions make reuse explicit, with pair comparison concentrated on conflicts/boundaries. Expected gains are fewer repeated comparisons, localized semantic errors and less fragmentation from unqueried edges. Systematic definition misreading remains possible, requiring random audits and source review.

This changes v2's promise: machine-accepted classes do not guarantee EQ certificates for every member pair. Strict equivalence follows signatures and reviewed rewrites, whose semantic extraction still needs evaluation. All-member EQ can remain an optional strict mode with explicit cost.

## 4. B: Sourced Concepts and Executable Relational Search

### Candidate sources and seeds

Retain both program generalization from real subgraphs and LLM proposals of missing relations/explained combinations. They share compiler, matcher and selector. Without reliable outcomes, learn reusable descriptive relations, not invented win/loss targets; legal direction and outcome association remain separately evidenced objects.

Sample connected 2–4-atom fragments within contract/request scope. Connections require actual parties, contracts, events or sourced relations, not shared case_id. Bucket by type structure and prefer different dispute families so long judgments do not monopolize resources.

Generalize compatible fragment pairs by replacing differing people/contracts/numbers with typed variables while retaining shared predicates, argument correspondence, identity/inequality and explicit time relations. Different statuses are not silently erased; broader status scope must be explicit. This is established relational learning, not a novelty claim.

Implementation buckets by predicate/argument types, enumerates atom correspondences, performs typed anti-unification, retains connected results, renames variables in first-occurrence order and sorts atoms. It does not promise a unique least generalization for arbitrary graphs. Initial caps: 50 seeds per dispute family, 100 fragment pairs per bucket, fixed sampling seed, recorded unsearched scope and diversity rather than frequency alone. Expanded candidates have at most six atoms, six object variables and two derived-definition levels, without cycles. These are resource limits, not theoretical optima.

The LLM sees source instances and existing definitions and proposes at most eight candidates per task, each with meaning, signature, AST, source instances and difficult neighbors. Reuse expressible structures; request source re-extraction for missing observations, operator registration for missing computation, and C bridges for legal evaluation.

| Candidate kind | Example | Admission |
|---|---|---|
| Composition abbreviation | Payment then notice under one contract | Valid bound query with saved expansion; reusable structure, not greater logical expressivity |
| Descriptive operator | Notice date minus awareness date | Typed inputs/units, tested deterministic operator, two explicit dates within the same event scope; otherwise no computation |
| Legal evaluation | Notice within reasonable time | Applicable rule, interpretive scope and bridge evidence; not a generic descriptive operator |

Sums, counts and all conditions can mistake missing records for complete sets. Initially allow existence of at least two explicitly distinct events; totals/full performance require separate completeness evidence. Time thresholds must be sourced to contract/law or marked descriptive bins, never renamed timely/unlawful without legal support.

### Execution and interpretable failures

Indexed joins return `(unit, binding, source_assertion_ids)`. A unit is a case/request/stage; related documents share a dispute family. Count support once per unit and retain every binding separately.

Distinguish conflict-free witnesses, explicit contrary source conditions, unknown identity/parameters and no recorded witness. The last is not real-world falsity; one failed binding does not refute all existential bindings.

Prefer real near misses differing in one atom, binding or time relation. Programs decide matching; independent source review decides fit to the natural-language definition. Model reviews are provisional references, not expert labels. Insufficient semantic evidence permits only query-candidate status, not a confirmed legal concept.

Development may use synthetic K1/K2 substitutions, time swaps, FOUND/ALLEGED changes, missing dates and explicit extensions to test code. These do not contribute real support or establish legal meaning.

### Local edits and ranking

Allow variable unification/separation, sourced equality/inequality, adding/removing a descriptive atom, retaining missing parameters, substituting registered operators, splitting definitions and fixing status scope. Do not rewrite facts to fit outcomes.

Store intermediate bindings for every join/comparison. Diagnose missing facts, type errors, cross-object joins or bad definitions before editing the relevant node. Exit branches without evidenced local repairs. RHDA motivates decomposed feedback, but our evidence is query witnesses/source review rather than known-answer program examples. Bound dependency depth as well as surface predicate count.

Per round: at most eight children per parent, twelve distinct structures retained and three repair rounds per candidate. Exhaustion retains failure reasons rather than forcing PASS. Rank candidates by: admission on types/sources/scope/reviewed negatives; fewer definition-match disagreements, separately reporting positives and hard negatives without using unknown as negative; more distinct-family valid witnesses without new confirmed semantic errors; then shorter, less redundant structure. New semantic labels rerank all extant candidates; old scores are not permanent truth and renamed candidates cannot bypass reviewed tests.

### Descriptive dictionary

Retain v2's decodable description-length objective for eligible descriptions, charging definitions, invocation bindings, constants and residual facts. Derived expansion/operator costs count; a short name cannot hide a long query.

Fix D to A's base records and minimize `L(definitions) + L(calls and bindings) + L(uncovered base facts)`. Preserve source text, IDs and statuses. Do not repeatedly add derived results to D to manufacture compression. Recomputable operators still require encoded names, definitions and necessary inputs. Start with greedy net savings, then single add/delete moves until no positive gain or budget; this is approximate, not globally optimal.

A pattern may be invoked repeatedly with different real bindings, unlike v2's one-call-per-pattern/unit cap. Repeating the same binding adds no coverage. Support remains deduplicated by unit. Rare legally grounded exceptions remain in C regardless of compression; unselected candidates and original facts remain inspectable.

```text
registry = frozen_base_types + reviewed_descriptive_operators
pool = generalize_real_connected_fragments(discovery_cases)
pool += propose_concepts_from_source_packets(registry)
for round in 1..3:
    for candidate in pool:
        compile_typed_bounded_query(candidate)
        execute_and_store_all_bindings_and_sources(candidate)
        separate_witness_absence_unknown_and_explicit_conflict()
        challenge = choose_real_near_misses_and_reviewed_test_cases()
        diagnose_definition_vs_binding_errors(challenge)
    archive accepted definitions and all unresolved failures
    if no candidate can improve within allowed edits: break
    pool = bounded_edits_and_top_structurally_distinct_candidates()
S = select_decodable_dictionary(validated_descriptive_candidates)
freeze_definitions_queries_and_selection_policy()
run_frozen_queries_on_confirmation_cases_without_repair()
```

Relative to pure WARMR, this adds language/concept acquisition rather than replacing relational semantics. Retain program seeds because LLM priors can miss patterns. Without validated targets, ADVENT target coverage or LRI majority support is not an acceptance rule.

### Outcome association only after label validation

The full project should eventually test which combinations relate to outcomes, but first identify party/request/stage and distinguish supported, denied, partially supported and procedural dispositions. Choose one clear binary request-stage task initially; do not label all other dispositions failures.

Freeze A. Within labeled training data, search short relations and compare regularized logistic regression on single facts versus facts plus combinations with dispute-family cross-validation. Add combinations by validation log-loss improvement, not training support or LLM opinion. Choose regularization, length and count in inner training splits; the final confirmation set cannot select candidates. This tests incremental information beyond constituent facts.

Features mean recorded witnesses in specified states, not real-world truth. Preserve missingness/source coverage separately. Permit positive witnesses or sourced explicit negation, never negation from silence. Retain similarly performing candidates with different factual compositions for legal review, following constrained subgroup-discovery ideas. NRI may later propose supervised combinations, but its Boolean labels, language and out-of-domain evidence do not justify direct replacement.

With postjudgment findings, call this retrospective outcome association. Predecision prediction requires separately versioned predecision material. Association is neither causal effect nor legal authority.

## 5. C: Sourced Rules, Bridges and Compilation

### Distinct sources and acquisition

Explicit statutory/case rules become sourced candidate rule cards. Implicit principles induced from case groups become separate hypothesis cards with supporting/opposing cases. Both can support research, but statistical majorities do not grant authority.

Cards preserve premises, conclusion, modality, exceptions, jurisdiction/time/stage, source spans, cross-references, priority, bridges, unresolved interpretation and review state. Missing information cannot be filled from the target outcome.

1. Retrieve original provisions, exceptions, definitions and cross-references; mark incomplete source packages.
2. Jointly draft premises, conclusions, exceptions and bindings using the shared type registry rather than creating unrelated atoms and forcing a later model to assemble rules.
3. Map every component to source. Request bridges for unexpressed legal concepts; NOTIFY cannot replace VALID_NOTICE.
4. Check variable scope, types, dates/units, signs, modality and finite support chains. Passing means formal executability only.
5. Test all-premises-present, missing necessary premise, established exception, different contract, wrong time/jurisdiction, explicit negative and missing information. Independent source interpretation must support expected answers; self-generated tests cannot certify the model's own rule.
6. Diagnose minimal differences: lost conditions, unexpanded references, wrong bindings or exception direction. Repair only evidenced components. At most three versions per card; retain competing interpretations as unresolved.
7. New normative rules, bridges and priorities need project legal review for the formal library. Marked automatic research candidates do not impersonate reviewed rules.

Retain restricted ASPIC+, explicit attacks and grounded labels from v2. Unknown exceptions follow each reviewed policy, not a universal absence assumption. C reads all eligible A facts; B assists retrieval without replacing premises or multiplying evidence weight.

### Derivation

Each request has a finite argument graph. Nodes are full sourced support chains; edges attack premises, conclusions or rule applicability. Distinguish strict deduction from defeasible rules. Apply source hierarchy, time and rule priority only when reviewed, not from rhetorical confidence.

Convert attacks plus reviewed priorities into defeats. Accept arguments with no effective defeaters, reject those defeated by accepted arguments, then accept those whose defeaters are all rejected, iterating to stability; leave the rest unresolved. Last-link compares the final defeasible rules supporting conflicting conclusions. Undefined priority leaves conflict.

Exception cards must distinguish proof-of-exception blocks default from proof-of-no-exception required. Unknown exceptions yield different results under these policies. Report accepted support/opposition, unresolved disputes, missing premises and source chains. No supporting argument does not prove the opposite. Incompletely formalized rules display sources and pending conditions without automatic conclusions.

Factors need not be necessary conditions. Retain direction, qualitative strength, request and evidence without making a factor sufficient for victory. Compare common factors and material differences first; only sourced bridges convert analogies into legal support/opposition. Otherwise present checkable analogy candidates. Do not invent numerical weights or add factors automatically. Missing facts can motivate inquiry but abduced hypotheses cannot become known facts.

A precise engine still produces wrong conclusions from a rule that conflates notice with valid notice. Therefore focus effort on source-to-rule/bridge errors and localized repairs. Program correctness alone cannot establish correct legal interpretation.

## 6. Fictional Running Example

All statements and rules here are constructed examples, not legal advice.

| Documentary statement | A representation |
|---|---|
| Court finds buyer fully paid K1 on May 1 | FOUND paid_full(buyer, seller, K1, May1) |
| Court finds K1 due May 10 and undelivered May 12 | FOUND due(K1, May10); FOUND not_delivered(K1, May12) |
| Court finds buyer sent K2 notice May 11 | FOUND notify(buyer, seller, K2, May11) |
| Buyer alleges K1 notice May 11, unresolved by court | ALLEGED notify(buyer, seller, K1, May11) |

A faulty B candidate for payment AND overdue nondelivery AND notice loses the shared contract variable, joining K1 payment with K2 notice. Source review identifies inconsistency with the same-contract intent. Unifying contract variables repairs it; then no full FOUND-channel witness exists. ALLEGED notice cannot be promoted.

Other cases may support same-contract notice and due dates. `notice_offset(K, Δ)` subtracts due date from notice date under shared K, notice-event scope and explicit dates. Δ=1 means one day later, not valid notice. After parameter/binding tests the operator can be reused.

A fictional rule says that within its scope, due delivery plus nondelivery and valid notice establish E, subject to recognized extension. C needs due, not_delivered, valid_notice and explicit exception semantics. B can retrieve a notice candidate but cannot supply validity. K1 lacks both found notice and validity evidence, so report missing premises, not E.

The useful feature is inspectable definitions, binding errors, repairs and legal premises, not an attractive factor name.

## 7. Feedback and Stopping

During development/discovery, B/C can request definitions/operators for sourced distinctions missing from A. A changes only through source and approved abstraction policy, never to improve outcome correlation. Legal sources may identify conditions to inspect; target outcomes cannot enter A.

Publish fixed versions. Changes to definitions, bindings or rules recompute all dependencies, including prior nonmatches/pruned candidates. Version one fully recomputes the bounded domain rather than pretending to have complete incremental maintenance.

Freeze types, patterns, selection and rules before independent confirmation. Confirmation runs and counts errors without repair. Any repair creates a new version and reclassifies those cases as exposed data. Stop at declared call/review/iteration budgets or a round with no admissible edit. Unresolved items remain deliverables with sources, candidates and missing conditions.

## 9. Supported Judgment and Remaining Evidence

The design addresses three gaps: A no longer maximizes retained model EQ edges; B can propose, execute and repair descriptions beyond the old vocabulary; C makes translation/bridging errors locatable within rule acquisition/review. This improves correspondence between questions and mechanisms, not measured real-data performance.

A small independent source-review set is essential for judging semantic repair. Without it, repeated automatic edits may merely increase self-consistency. Candidate generation/execution can be implemented first, but self-evaluation cannot replace this evidence.

## 10. Comparison with Original Alternatives

Embedding/LLM methods still retrieve and judge, but explicit definitions prevent chained A≈B≈C merging. The PDF already had conservative merges/boundaries; initialization, edits, acceptance and recomputation are additions. DBSCAN-like methods can propose groups but distances do not preserve polarity, role, state or object scope; silhouette scores are insufficient.

FP-Growth suits correctly formed discrete items. Whole-case payment/notice bags lose shared-contract identity, whereas verified bound-relation features can still be efficiently enumerated by FP-Growth. gSpan enumerates graph structures but needs normalized nodes/edges, temporal/numeric semantics and interpretability selection; real subgraph seeds can reuse its search ideas while adding concepts and evidenced repair.

The exact ANCO-HITS version/setup remains unverified, so no replacement superiority is claimed. Ranking never substitutes for bindings, sources or law. Direct LLM explanation can draft candidates/prose; explicit premises, exceptions and defeats distinguish missing premises, counterevidence and interpretive disputes.

## 11. Implementation and Validation

Start in one domain, not all causes of action. Filenames do not establish domain. Group related dispute documents, exclude empty sources, check facts against text, then split development/discovery/independent confirmation according to available samples and review budget. The 6,954 documents are not 6,954 independent cases.

Implement shared objects/provenance and A extraction/registry first; B bounded syntax, exact matching, program seeds and LLM proposals next; then localized repair, with a small reviewed legal-source set connecting C. Begin with payment–same contract–notice–exception structural tests before real domain rules. Disable outcome association without reliable labels rather than generating labels to self-certify.

| Claim | Required evidence | Response to failure |
|---|---|---|
| A reduces bad merges/drift | At fixed review budget: source-supported mapping accuracy, dangerous merges, missed merges, pending rate, version regressions and extraction recall | Separate extraction, definition and retrieval errors; reject-all cannot win on precision |
| B concepts/repairs help | Matched candidate/call budgets: valid new relations, real cross-case recurrence, binding errors; separate concept/edit ablations | Retain simpler program seeds without net benefit; extra calls cannot establish mechanism gain |
| Combinations add predictive information | Validated labels; improvement over single facts on undiscovered data; dispute-family uncertainty | Without stable gain, call them descriptions rather than predictive factors |
| C translation/inference is faithful | Independent law review, premise/exception/binding tests, traceable support and appropriate unresolved states | Repair translation from sources, not engines to match outcomes |

These real-data experiments have not run. Reused development review examples are repair/training evidence, not independent correctness tests. Report machine-accepted, human-confirmed and pending counts separately; preserved source records do not necessarily enter formal reasoning.
