# Legal AI 核心算法设计

2026-09-29 · 研究与实现建议 · 尚无端到端实验成绩

## 先给出选择

本项目的 A/B/C 划分可以保留，但三者解决不同问题。A 建立可复用的事实表示；B 从多个案件中发现反复出现、具有对象关系的事实组合；C 把有出处的事实接到经核验的法律条件与论证上。C 可以直接使用 A 的事实，不需要等 B 找到统计模式。B 的模式不能自动变成法律规则。

推荐采用现有方法的明确组合，不给组合另起一个暗示原创的新名字：

| 模块 | 首选算法 | 主要输出 | 主要取舍 |
|---|---|---|---|
| A | 来源约束抽取＋正向证据约束的局部相关聚类＋版本修复 | 有实例身份和陈述状态的事实、稳定类别、合并依据 | 用更严格的准入降低误合并，接受更多未决项和核验成本 |
| B | 有界 WARMR 式关系查询枚举＋关系字典集合覆盖优化 | 小型关系模式集、精确见证、按独立单元计算的支持度 | 先限定可枚举的模式语言，再压缩重复描述；不承诺挖出所有法律规律 |
| C | 经审阅的规则编译＋有限 ASPIC+ 论证图＋grounded 语义 | 支持、反对、未决状态，以及从法源到原文的论证轨迹 | 对当前规则与证据作可复查推导，保留冲突和缺口；不自动裁判 |

A 保留完全链接准入条件：“同簇中每一对不同语义签名都必须通过等价判定”；在这个条件下，用现成整数规划（把是否合并写成0/1变量，在约束下选择最佳组合）处理相互竞争的合并，而不是由到达顺序决定。B 的关系查询是在模式中重复使用同一个变量，例如付款和未交付必须涉及同一份合同。B 再把模式定义、每次使用的对象绑定和未覆盖事实一起计费，选择能减少总描述长度的组合。C 的 grounded 语义先接纳没有攻击者的论证，再接纳其所有攻击者都已被接纳论证击败的论证；反复计算到不再变化，剩余循环争议保留未决。

这些选择是可实现的研究起点。下文分别说明算法、为何选它、何时应换成替代方法。示例全部为构造材料，法律规则也仅用于解释计算，不代表任何司法辖区的真实法条。

## 1. 需求与数据边界

### 1.1 哪些是项目已经要求的

本次只用原始 PDF、团队分工消息、完整 Evidence-to-Conclusion 图和本地数据定义需求。白板及其手写内容完全排除。

原 PDF 已要求原子事实抽取、以有出处的法律角色替代案件专名、谓词—论元表示、保留极性/模态/时间/事实状态、按法律背景检索候选、用模型区分等价/上下位/兄弟/矛盾/无关/不确定、保守聚类、防止链式合并和语义漂移、保留来源。它还提出后续胜败模式挖掘，并列举 FP-Growth、gSpan、ANCO-HITS。团队消息明确分配抽取、聚类、模式挖掘、评价和法源抓取，建议从约 1,000 个样本开发基础逻辑。这不是“原文没有算法”：A 已有详细的方法框架，缺的是若干执行规则及可比较的完整实现。

完整流程图要求事实模式、因素/子测试、要件、请求/抗辩、争点与结论的连接，以及法源对规则/测试的依据关系。它没有决定用 ASPIC+，也没有决定如何从文字可靠编译规则。因此 C 是合理的系统模块，但其具体推理语义属于本方案的实施选择。

| 类型 | 内容 |
|---|---|
| 明确要求 | 原子事实、角色/论元、保守等价聚类、来源、跨案模式、法源与规范层的连接 |
| 必须作出的实现选择 | 实例 ID、陈述状态、聚类准入与修复、查询语言与支持单元、规则语义、版本失效机制 |
| 可选研究扩展 | 自动法律本体归纳、联合可能世界优化、预算主动复核、自动规则归纳、前瞻预测、复杂价值与举证论证 |

可选扩展不作为第一版能够运行的前提，也不冒充团队已同意的目标。

## 2. 共同表示与贯穿例子

### 2.1 保存什么，什么进入计算

每个来源片段保存 `doc_id, field, start, end, text_hash, quote`。原网页段落位置若可核验则另存；本地字段字符偏移只能指回当前快照，不冒充原判决段落号。所有后续节点保存输入 ID 与版本。

```text
Assertion {
  assertion_id, document_id, litigation_family_id,
  claim_id?, stage?, jurisdiction?, legal_context?,
  predicate_id?, args:[(slot, entity_or_event_id)],
  polarity: POS|NEG, modality, time_interval?,
  statement_status: ALLEGED|DENIED|FOUND|ADMITTED|UNRESOLVED,
  speaker, source_span_ids,
  interpretation: ACCEPTED|AMBIGUOUS|INVALID,
  candidate_interpretations[], type_version, extraction_version
}
```

`statement_status` 描述文书怎样记载该命题，不是真实世界真值。`interpretation` 表示系统是否明确读懂及绑定这条陈述，两者不能合并成一个 confidence。否定命题是显式记录，缺失命题没有自动补出的 NEG。日期和实体不明确时保存候选与原文，不能靠最近位置强行连接。

实体身份限于案件内部；跨案共享“买方”这个角色类型，不共享同一个买方实体。角色带合同/事件范围，某人在 K1 是买方不代表在 K2 也是买方。事件 ID 与合同 ID 不互相替代。内容谓词可以共用；**等价陈述簇必须同时保留极性、模态和状态分区**。例如 `FULL_PAYMENT × ALLEGED` 与 `FULL_PAYMENT × FOUND` 是两个规范化陈述类，上层可以同属“付款内容”family。family 是上位组织，不自动产生等价、支持强度或下游可替换性。

A 的 accepted 记录进入默认查询视图；ambiguous 候选保存在数据库并展示给复核者，不默认投票成一个已接受事实。B 的主体视图默认只选明确记载的法院认定与明确无争议事实，同时单独运行 allegation 视图；跨视图模式必须在查询中显式写状态。同一视图中若相同论元、相同时间范围同时出现p与¬p，保留两条来源断言及CONFLICT链接；B默认的无冲突查询视图排除这组命题，另保存冲突视图。C仍能读取两条来源并构造相反论证，不能因B的筛选丢失抗辩。C 的 factual view 单独配置，不把主张直接当已确立前提。

### 2.2 一个小例子

在同一份假想判决 J1 中：

| 来源 | 原文简写 | 结构化解释 |
|---|---|---|
| s1 | 买方主张已付清 K1 价款 | `paid_full(b,s,K1)`, ALLEGED |
| s2 | 法院查明买方已结清 K1 价款 | `paid_full(b,s,K1)`, FOUND |
| s3 | 法院查明 K2 项下尚未交付 | `not_delivered(s,b,K2)`, FOUND |
| s4 | 买方称卖方明确拒绝 K1 交付 | `refused_delivery(s,b,K1)`, ALLEGED |
| s5 | 判决另载 K1 尚未交付，但未认定有拒绝行为 | `not_delivered(s,b,K1)`, FOUND；不生成 `refused_delivery` |
| s6 | 对 K1 是否延期，双方各执一词，法院未解决 | `extended(K1)` 与 `¬extended(K1)` 为争议陈述 |
| s7 | 未找到 K1 到期日期的认定 | 没有 `due(K1)`，状态未知 |

记号约定：例子中的not_delivered是显式“未交付”命题，not_extended与¬extended表示同一个显式否定命题；它们都不表示“数据库里没查到”。实现中统一用带polarity的literal，再生成显示名称，避免重复否定。

另一个案件 J2 以不同姓名写“法院认定价款已经全额结清”，可映射到与 s2 相同的规范化类型，但保留自己的当事人和合同实例。`not_delivered` 与 `refused_delivery` 不等价：前者没有表达明确拒绝这一额外行为。仅当任务词典已审阅并明确规定单向蕴含条件时，才另存关系；不因词语接近就合并。

## 3. A：正向证据约束的局部相关聚类

### 3.1 任务与首选理由

输入为重分段后的文书、少量审阅后的角色/谓词约束和已发布类型字典。输出为上述 Assertion、规范化类型定义、成员映射、成对判定缓存和审查队列。优化次序是：先约束法律重要误合并，再在覆盖与调用预算内减少重复类型。首版不优化未知真实类别数量，也不假设法律类别呈球状或有固定 k。

选取 EDC 的抽取—定义—检索—规范化结构，落实原 PDF 的保守聚类，所有簇满足完整的正向证据准入。在此基础上采用受约束的相关聚类：用整数规划在相互竞争的合法合并中选择保留最多已核验等价对的划分。首版每条通过的边权重固定为1，不把未经校准的模型分数当概率。优化器不创造EQ证据，也不保证判断器正确。

### 3.2 抽取与判定器的明确接口

1. 按段落来源滑窗抽取，每个窗口同时要求输出原文支持范围、谓词、论元槽、对象指代、极性、模态、时间、说话者、陈述状态。窗口重叠只用于上下文。一个原子事实只有一个主关系；并列关系拆开，但否定、条件、嵌套主张的作用域保留。
2. 机械校验 quote/offset/hash、槽位数量、角色类型、局部 ID 引用、时间区间格式。不得从“公司”补出 controller、从未提供补出拒绝；没有原文支持的槽填 unknown。
3. 第二次模型调用逐槽返回 `SUPPORTED / CONTRADICTED / NOT_STATED`，必须引用原片段。任何必需槽非 SUPPORTED 则修正一次；仍失败进入 ambiguous/invalid。两次调用没有独立性保证，属于可测的模型判定器，不是事实认证。
4. 重叠窗口中完全相同命题、实例、状态和来源合并为一条 Assertion，来源列表并集。同命题不同说话者/时间/状态仍分别保存。局部身份只接受明确指代证据；歧义保留候选，不跨合同拼接。

成对比较的对象是去掉案件专名、保留角色/槽位/法律关键限定的**语义签名**，实例 ID 只在映射中保存。先区分两层：TYPE_EQ 比较变量抽象后的内容谓词和定义性限定；规范化陈述类再按状态/极性/模态分区。实例去重另外要求论元同指和时间兼容。完整具体事实不能与一般类型定义直接作双向蕴含；算法中的 definition 检查针对同粒度的抽象签名。先机械检查 arity、角色方向、状态、极性、模态和已知时间关系。若不兼容，直接 NON_EQ；关键项缺失则 UNKNOWN。

其余候选由双向蕴含判定器读取原句、签名和冻结的类型范围，分别回答：

```text
Does x imply every required slot and qualifier of y?
Does y imply every required slot and qualifier of x?
For each direction: ENTAILS / CONTRADICTS / NOT_ESTABLISHED,
with source spans and the exact unmatched qualifier.
```

调用交换顺序再判一次。仅当两次都双向 ENTAILS、槽位对齐通过、没有新增限定时记 EQ。单向成立记 SUBTYPE；相反极性且相同对象/时间范围才记 CONTRADICTORY；同主题不同条件记 SIBLING；缺支持/模型分歧记 UNKNOWN。已审阅同义模板可直接得到 EQ，并记录模板版本。上述判断枚举是完整的程序接口，语义判断误差仍需专家样本测量。**多次模型同意不是概率校准或法律真值证明。**

### 3.3 检索、完整准入与全局竞争

法律语境先分块，陈述状态等在规范化陈述类中分区。只把已知不兼容作为硬排除；未知语境单独标记并允许兼容候选补检，不能将 unknown 当成不同法律背景。块内 BM25 与嵌入各取前 k，用 `sum 1/(60+rank)` 融合；完全相同签名优先。

候选类型有冻结定义、必需限定、排除项及不同语义签名。比较顺序为已知冲突、最远/边界成员、其余稳定 ID。任何失败即可拒绝本次完整准入，但先前正向判定仍保存。只有每对签名都有有效 EQ 记录，才允许同簇。缓存键包含语境、签名、原文区别和判断器版本；模型把两段原文抽成同一 AST 不足以证明它们可以免检。

所有已验收 EQ 构成正向图 E+。令 z[i,j]=1 表示两签名同簇。不通过EQ传递闭包补出未查询边。未知、不确定、非等价、已撤销的边均不允许 z=1，但在数据库保留其不同原因，不统称负例。

```text
maximize  sum_(i,j in E+) z[i,j]
subject to
  z[i,j] = 0                         if (i,j) not in E+
  z[i,j] + z[j,k] - 1 <= z[i,k]       for every triple and permutation
  z[i,j] in {0,1}
```

三角约束保证输出构成划分，正向边约束保证每个簇是已核验图中的团。目标是保留已验证的可复用关系数量，不是预计法律损害。若有多个最优解，第二目标最小化相对旧版本的成员关系变化，再按稳定 ID 打破平局；不能用 epsilon 混合权重改变首要目标。求解器未证明首要目标最优时，直接保留当前最佳可行解并报告 gap，不谎称完成字典序最优。

一个竞争例子：只有 a–b、a–c、b–d 三条已核验 EQ。贪心先合并 a–b 后只能剩两个 singleton；整数规划可以选择 {a,c} 和 {b,d}，保留两个等价对，并且没有通过未经核验的边串联。例子说明目标差异，不证明自然语言等价判断正确。

```python
canonicalize_batch(assertions, previous_version, budget):
    V = extract_validate_and_sign(assertions)
    pairs = retrieve_candidate_pairs(V, previous_version, k)
    for x,y in priority_order(pairs):
        if budget.exhausted: break
        relation[x,y] = cache.get_or_judge(x,y,profile_version)
    Eplus = current_valid_EQ_pairs(relation)
    for component in connected_components(Eplus):
        if size(component) <= 80:
            partition = solve_clique_partition_MILP(component, time_limit=60)
        else:
            partition = complete_link_greedy_then_local_improve(component)
        if no_feasible_solver_result: partition = verified_greedy_fallback(component)
        assert every_internal_pair_in_Eplus(partition)
    publish_only_definitions_equivalent_to_every_member()
    return partition, pending_pairs, decisions, objective_and_solver_status
```

较大分量的确定回退：按已核验边的稳定顺序构造完整交叉准入的贪心划分；然后最多5轮尝试单节点迁移、拆出再重入、整簇合并，只有完整交叉 EQ 且目标严格提高才接受；固定遍历顺序。它没有最优保证。候选检索漏召回会限制可合并边，优化器不能补救。

### 3.4 增量、分裂与恢复

新增批次先生成候选并核验，包含竞争簇的整个正向连通分量重新求解，不只把新成员塞进首个通过的簇。相同目标下第二目标尽量少改旧关系。若两个簇都能容纳一个新成员而彼此不能合并，优化器选择一边；另一条 EQ 仍记为“已核验但当前划分未采用”，不是语义非等价。

错误分为抽取、身份、成对判断、定义/语境错误。先修正原始 Assertion 或撤销相关判定，再重算受影响分量。定义的候选先取旧定义，否则取最短签名的规范表达（长度平手按ID），逐成员运行同一双向蕴含判定。失败则允许一次依据未匹配限定的改写，再全量核验；仍失败保留分组与未发布标签供人工审阅。定义只有与簇内每个抽象签名等价才发布；定义更宽/更窄时生成新的 parent/child 关系或暂缓类型发布，不能靠改宽定义容纳错误成员。旧版本保留，splits/merges写 lineage。

正向图变化可使一个旧分量拆开，也可连接多个分量，因此增量范围取变更前后分量并集。一次自动抽取修正、一次分量重解后仍有语义冲突则送审；不反复调用模型直到输出 EQ。singleton 事实不删除，复用率、未决率与 singleton 率进入评价。

### 3.5 预算、性质与选择依据

原型 k=20、每条事实最多100次成对判断、分量≤80用60秒MILP，较大分量用上述有限回退。开发集比较 k∈{10,20,40}、判断预算∈{50,100,200}；选择满足预先约定误合并上限和最低复用要求时覆盖最高的配置，成本作为平局准则。等价边权默认1，无额外校准数据成本。加权概率版本只作后续变体，需要单独校准与预算核算。

O(m²)候选对和O(m³)三角约束是最坏规模，MILP最坏指数级，因此必须按分量和时间限制运行。模型成本、求解时间和人工成本全部报告。给定正确的EQ判断，完整准入排除簇内非等价对；给定固定正向图，求解至最优的分组保留的已核验对数不会少于同约束的贪心可行解。**这两个性质都不保证更高法律准确率。**若新图包含错误EQ，优化器仍会利用它。

首选这一组合的理由：它保留完全链接的安全条件，同时避免贪心在多个合法合并中因早期选择损失复用。当前缺少可靠等价概率，先用单位边权，避免精致但未经验证的风险函数。若MILP只改善图目标、未提高等预算下正确复用或下游表现，就退回惰性完全链接。

### 3.6 强替代方法比较

| 强替代 | 机制和具体局限 | 本方案差异 | 为什么可能有用 | 成本/失败条件 | 决定性实验 |
|---|---|---|---|---|---|

## 4. B：有界关系查询挖掘与可解码的模式字典

### 4.1 任务、表示与首选理由

输入是冻结的 A 版本、固定的案件/请求/阶段范围、合法谓词和连接方式。输出是可以执行的查询模式、每个模式的支持单元、具体事实见证，以及描述这些事实的紧凑模式字典。

首选 WARMR 式逐层查询搜索，因为需要表达任意有限元关系、共享合同变量、时间比较和明确的状态条件。然后以**总描述长度**选择模式集合：支付一次模式定义的长度，换取多次使用这个模式描述事实的节省。采用 KG-MDL 的保留绑定原则，为固定候选和见证写出可解码的编码，再用整数规划联合选择字典与覆盖。SLIM 式贪心改进作为同编码下的直接对照与超时回退。以下编码是本项目的适配方案，不声称等于这些方法的原实现，更不继承它们的实验成绩。

这个选择直接处理当前没有可靠 outcome 标签的条件。它寻找可重复的记录结构。法律重要性与压缩收益是不同目标，字典之外仍保存完整候选与专家标记的稀有模式。标记稀有模式不会偷偷改变已报告的压缩目标。

### 4.2 有限模式语言

```text
P(U) := exists b,s,K,t ... :
        paid_full(U,b,s,K,FOUND)
    AND not_delivered(U,s,b,K,FOUND)
    AND due(U,K,t,FOUND)
```

`U` 是一个请求/阶段分析单元，`b/s/K/t` 分别是买方、卖方、合同和时间变量。模式在不同案件中复用变量结构，在一个匹配中同名变量必须绑定相同 ID。匹配默认采用同态语义：不同变量可以映射同一实体，只有显式 `neq(x,y)` 才要求不同；同一事件不能重复充当逻辑上要求不同的两个事件时也要显式加入 neq。gSpan 对照需通过等价的身份约束适配，不能悄悄比较两种不同匹配语义。

原型使用 2–4 个内容原子、最多 6 个非 U 变量、无函数符号、显式否定谓词、有限角色/时间关系词典。状态是谓词参数或视图固定条件。关系图在去掉共同 U 后必须通过实体/合同/事件变量连通；仅因“都在同一案件”连接不算关系模式。每个变量必须出现在一个内容原子中，时间/不等式过滤只作用于已绑定变量。词典中的上下位 family 不自动替代底层谓词。

模式的常量只允许预先声明的状态、法律类别和粗时间关系，不允许从发现集任意挑姓名、合同编号、日期阈值。阈值若要学习，限于开发集预设网格，冻结后再发现模式。

### 4.3 候选生成、计数与剪枝

起点为所有允许的一原子查询。每次添加一个内容原子，至少共享一个非 U 变量，新变量必须满足槽位类型。随后按固定顺序添加允许的时间/neq 过滤。不能通过加入 family 上位词偷偷泛化已有原子；概括与细化是不同操作，本版只做合取扩展。

候选编码：对相同类型变量的所有规范重命名与最多 4 个原子的排列，选择字典序最小的序列，绑定槽顺序保留。它消除 alpha 重命名和原子顺序重复，不声称解决所有含背景公理的逻辑等价。完全重复原子删除；审阅过的蕴含冗余可删，但必须保留使用的公理版本。仅因为发现集上 support 一样，不能删除语义不同模式。

匹配使用按 `(predicate, status, arg slots)` 建索引的关系表。每次扩展对父查询的变量绑定做哈希连接，再过滤类型、身份、极性、时间。见证保存 `unit_id, variable_binding, sorted assertion_ids`，重复句子与多个同义来源不会重复增加事实或支持。

分析单元为 `case_id × claim_id × stage`，保留具体裁判身份，另存 `litigation_family_id`。发现语料按诉讼组/请求/阶段预先选一个指定裁判的完整来源快照，其他来源只在明确允许的回顾视图中加入，不能跨阶段自由拼接。一个模式即使在某单元有多种见证也只计一次；主支持数按不同分析单元计数，另设 family_support 按不同诉讼组计数，用于最低独立重复次数约束。同一 family 的多个请求可以增加 unit_support，但不增加 family_support；统计区间与数据划分均按 family 处理相关性。

分母是该次任务固定的合格分析单元集合 N。主支持率是“至少存在一个合格见证的单元数 / N”；另报 family 支持率及其固定 family 分母。对未观察到模式的单元记录 `NO_RECORDED_WITNESS`，不推导现实中的模式为假。不对每个模式临时重选“可观察案件”作为分母。

```python
F[1] = permitted_single_atoms()
for size in range(1, max_atoms + 1):
    for q in canonical_order(F[size]):
        W[q] = exact_join(q, frozen_assertion_view)
        sup[q] = count_distinct_unit(W[q])
        fsup[q] = count_distinct_family(W[q])
        if sup[q] < min_support or fsup[q] < min_families: continue
        save_frequent(q, W[q])
        if size < max_atoms:
            for atom in legal_one_atom_extensions(q):
                q2 = canonical_code(q & atom)
                if within_limits(q2): enqueue_if_unseen(F[size+1], q2)
# Stop at fixed bounds, exhausted frontier, or resource cap.
# Timed-out queries are UNKNOWN_COUNT, never support=0.
```

安全剪枝只利用已知父查询支持数：增加一个合取条件的匹配集合不会扩大，因此父查询不频繁时后代也不频繁。**不使用“任意删一原子都要频繁”的简化 Apriori 检查**，因为删除原子可能破坏类型/连接前缀，产生语言之外的查询。枚举只覆盖上述可由合法前缀构造的语言；不把受限语言的完备性扩展到全部逻辑查询。设置超时或候选上限后进一步失去枚举完备性，报告已完成层数与未完成队列。

### 4.4 最终集合选择：可解码的字典与集合覆盖

首先去重每个单元的 ground atoms。来源、原文、实体类型表、谓词词典和版本另外无损保存，作为固定元数据。压缩目标只评价事实关系层，不是整份判决的文本压缩。候选及其全部见证先冻结；未完成的候选不参加本轮选择。

采用以下明确编码，使成本不随选择顺序改变：

- 数据 token 用 2 bit 区分 literal、macro 和单元结束。literal 编码谓词 ID 和按槽位类型编码的全部实体 ID。macro 编码模式 ID 与每个变量的绑定，展开得到原子集合。
- 每种类型 n 个实体按稳定 ID 排序，索引用 `ceil(log2(max(1,n)))` bit；谓词 ID 的宽度由冻结词典决定；编码字母表使用带极性、状态及所需模态限定的关系符号，或为这些字段另加固定宽度。不能只编码裸动词而丢掉区别。不同变量可以同指，逐个编码，不使用要求实体互异的压缩方式。
- 模式 ID 使用候选规范排序中的整数，统一取固定宽度 `ceil(log2(max(1,M)))`，M 为本轮完整候选数。编码头保存该宽度，不必传输未选模式。每个选中模式的字典项保存自己的 ID、原子数、变量数、变量类型、各原子的谓词和变量/常量参数，以及时间/不等式约束。
- 字典条目以标记位开头，0 为结束、1 为新条目；需要变长整数的地方编码 n+1 的 Elias-gamma。谓词的已知 arity 决定参数个数，变量/常量引用有区分位。字典结束和各单元结束标记的成本固定。

所有 token 可无歧义解码。某个 macro 只允许使用已核验见证，因此展开不会创造新事实；解码对 literal 和展开结果取集合并集。重叠事实只需覆盖一次，但每次宏使用的完整成本都付出。原来源仍可通过单元与原子 ID 表追溯。

令 x_p 表示选模式 p，z_o 表示使用其见证 o，r_f 表示保留事实 f 的 literal。L_p 是完整模式定义成本，c_o 是带绑定的 macro 成本，c_f 是 literal 成本。用混合整数线性规划（MILP，本版只需0/1变量）求解：

```text
min  Σp Lp·xp + Σo co·zo + Σf cf·rf + 固定头/元数据成本
s.t. rf + Σ{o: f∈o} zo ≥ 1                     每个事实必须可重建
     zo ≤ xpattern(o)                          未选模式不能使用
     Σ{o属于(p,u)} zo ≤ xp                     每模式每单元最多一次
     hpg ≥ zo  对每个属于(p,g)的见证
     hpg ≤ Σ{o属于(p,g)} zo                    hpg = 该诉讼组是否使用p
     Σg hpg ≥ 3·xp                            至少在3个独立诉讼组实际使用
     xp,zo,rf,hpg ∈ {0,1}
```

这里明确区分“存在匹配见证的发现支持”和“压缩解实际采用的使用次数”。最低发现支持为5个诉讼组；选择阶段至少3组实际使用，避免字典只靠一个长案件获益。每模式每单元最多一次是有意设置的压缩使用限制，不是支持度定义或逻辑必然条件，会牺牲对同一案件内部大量重复的压缩。所有绑定仍保存在见证表。必须比较解除该限制、允许多个macro的变体，检验它是否真的改善跨案发现。上述目标允许重叠模式，固定成本和覆盖约束共同决定是否值得多付一个定义。

```python
candidates, witnesses = freeze_completed_search()
initial = all_literals()                       # 总是可行
initial = better(initial, feasible_greedy_cover(candidates))
solution = solve_binary_program(time_limit=300, incumbent=initial)
if no_feasible_solution: solution = all_literals()
assert all_constraints_hold(solution)
assert decode(encode(solution)) == original_atom_sets
return dictionary, bindings, residuals, objective, bound, solver_status
```

回退贪心也必须满足相同约束：从全 literal 开始，对每个未选模式，在每单元选一个节省最多的见证，再枚举按净节省排序的诉讼组前缀，至少3组；扣除完整定义成本后选最大正收益的模式及使用集合。已有覆盖减少后续收益，按当前 uncovered 集合重算。不能把不满足独立使用约束的便宜解当对照。

运行最多300秒，保存最好可行解、下界和相对 gap，输入/版本/求解器种子固定。到限有可行解可用但标记 `FEASIBLE_NOT_OPTIMAL`；没有候选获益时保留空字典和全部 literal。相同目标下只接受不差于初始可行解的结果。

**条件性质**：全部约束和解码校验通过时，选出的字典能重建冻结事实集合；求解到最优时，长度不超过同候选、同编码、同约束的任何贪心解。它不保证法律重要性，也不保证未见案件的压缩。求解未到最优时不能声称全局最优，候选不完整时不能声称对全部模式最优。

选择整数规划的原因是冗余模式会竞争同一批事实，逐个加入的顺序可能影响总结果。固定小候选批次可以让现成求解器直接处理这个竞争。若自然案件上只有很小编码收益却增加大量时间，保留同编码的贪心版本。与 KG-MDL 使用不同编码时，不直接把两者内部 bit 数当统一成绩；另用共同编码评估、专家审查和独立复现比较。

### 4.5 实际执行例子

对 J1：s1 和 s2 都保存，默认 FOUND 视图只使用 s2。`paid_full(b,s,K) ∧ not_delivered(s,b,K)` 用 s2+s3 尝试时，第一条绑定 K=K1，第二条要求 K=K2，连接失败。加入 s5 后，s2+s5 是 K1 的合法见证。s4 是 ALLEGED，且谓词是 refused_delivery，既不能替代 s5，也不能作为默认 FOUND 模式的证据。`paid_full ∧ not_delivered ∧ due` 因 s7 缺失没有完整见证；这不意味着 due 为假。

在多个其他案件出现相同变量结构时，按分析单元计主支持，按 family 另计独立重复。进入字典与否还要算定义成本。示意计算：若某种固定编码下一组三原子 literal 共 33 bit、相同绑定 macro 为 7 bit，每次使用可节省 26 bit；完整模式定义若增加 70 bit，一次使用不合算，三次使用才可能净省 8 bit。这里是说明计算的假设数字，实际长度由完整编码器输出，不是数据集结果。

### 4.6 参数与资源

默认上限为 4 内容原子、6 变量，`min_support=max(5,ceil(0.02*N))` 且 `min_families=5`，50,000 个候选或每批 2 CPU 小时上限。单查询超时保留待续游标，不作为不频繁剪枝。见证可落到 SQLite/关系数据库，支持计数先用 EXISTS 避免全量笛卡尔积；做 cover 才枚举见证，仍需报告覆盖计算超时。达到资源上限返回当前完整计算的候选范围内最好可行字典及 `INCOMPLETE_SEARCH`。

开发集比较原子上限 {3,4,5}、支持阈值 {1%,2%,5% 且≥5 family}，按固定专家审查分钟数下的有效非冗余模式产出选择，要求最低案件覆盖，随后冻结。复杂度最坏随谓词和变量数指数增长；完整见证枚举可能爆炸。限定语言是资源取舍，不能包装成免费优势。

### 4.7 强替代方法比较

| 强替代 | 机制和具体局限 | 本方案差异 | 为什么可能有用 | 成本/失败条件 | 决定性实验 |
|---|---|---|---|---|---|
| gSpan＋同样 typed incidence graph、状态/身份、支持计数 | 保留图结构，DFS 规范码去重；适合频繁连接子图。多元谓词须编码为关系节点，匹配语义须统一 | 直接按槽位和共享变量生成查询，语言中直接限制对象/时间 | 减少不符合允许关系语法的中间子图与转换开销 | 图结构更一般时可能牺牲模式，成熟 gSpan 可能更快 | 相同可表达模式、输入和预算下，比较正确候选召回/执行时间；gSpan同样快则不声称搜索优势 |
| 同候选、同编码、同约束的贪心集合选择 | 便宜、可解释，但局部覆盖可能阻断更好的组合 | 联合优化模式与见证使用 | 固定目标达到最优时长度不差于贪心 | MILP可能只改善几bit而不改善专家效用 | 锁定候选与编码，比较gap、时间、有效模式；无实际收益即回退 |
| WARMR 枚举＋简单 top-k/去重 | 已解决关系绑定和支持计数，不能声称我们首次做关系模式 | 增加有绑定的集合编码，联合选择字典与覆盖 | 避免大量近重复模式占用专家审阅位置 | 偏好常见长模式，可能遗漏稀有但重要的组合 | 同候选、同输出/审查预算，比较新增有效信息、复现和稀有模式损失 |
| KG-MDL / GraphMDL+ | 已保留关系与共享端口、选择小型字典，KG-MDL 有实际 cover timeout；不是普通扁平压缩 | 固定案件边界/陈述视图/模式语言，同时报告 unit/family 支持，直接存查询绑定 | 目标对准跨案重复，避免一个长案件/常见 schema 结构主导 | 若给 KG-MDL 同样边界和约束，优势可能消失；其搜索可能更高效 | 同样事实图和约束、相同 CPU/专家预算；比较共同编码下的长度、法律有效模式与跨案覆盖 |
| 关系查询特征＋FP-Growth/闭合项集＋SLIM或Snor | FP-Growth 找共现，SLIM压缩，Snor允许重叠减少冗余；给完整关系特征后可很强 | 对组合直接共享变量并保存 witness，再以关系层编码选择 | 当多特征须共享未知合同/事件时，不把存在不同见证误当共同见证 | 完整特征已足够且组合重验绑定时，正确性优势消失 | 固定共同查询库与绑定复核，只比较增量生成和集合选择成本 |
| LLM语言偏置＋ILP（MAXSYNTH/ADVENT式） | 可提出辅助谓词并搜索可执行规则，通常需要标注目标/正负例 | 首版固定可解释语言，做无标签描述性搜索 | 避免在没有可靠目标时诱导错误规则或生成噪声 | 需要发明新概念或长模式时，本版可能漏检 | 后续给相同标签/背景与总预算，比较新候选的独立确认增量 |

FP-Growth 可作为已有关系特征上的高效组件；gSpan 是必须认真比较的关系搜索器。ANCO-HITS 所见一手应用是带正负边二部图的共同分组/排序，既不是频繁项集也不是关系查询枚举。只有先定义案件—authority 等二部图、正负边及排序任务时才适用，不强塞进当前 B。

B 的首选不是因为“比 gSpan 更懂关系”，而是目前任务语言可明确限制为小型、有状态、按请求绑定的关系查询。若数据证明合法模式更适合一般图结构，或者 KG-MDL 在同等约束下更有效，就采用它。新颖性不能来自 WARMR＋压缩这几个名称的组合。

## 5. C：经核验规则与有限论证图

### 5.1 任务与首选理由

输入是 A 的事实快照、一个争点下经审阅的法律规则包、明确的来源视图与优先关系，可选输入 B 的模式见证。输出不是单一 WIN/LOSE，而是每个要件/请求命题的支持论证、反对论证、接受状态和缺失前提。

首选 ASPIC+ 的论证构造与攻击区分，用 grounded 语义得到一个确定的谨慎接受集合。理由是本项目图中既有支持也有击败、抗辩和例外，需要区分“反对某事实”“反对推论的结论”“否定某条规则这次可以适用”。普通合取清单不能表达这三种冲突。成熟 ASPIC+ 引擎若支持下述语义，优先复用；本方案不声称自写求解器比成熟引擎更准确。

### 5.2 获取并编译规则，而不是从统计模式生成法律

1. 从限定争点与案件引用提取法源候选，保存原文、段落、裁判时间、辖区、效力与适用范围。先检索原判决实际引用材料，再检索同范围法规与明确例外；回顾性分析允许使用实际引用，但要标记为事后来源。
2. 模型依据规则包的共享谓词表输出规则草稿及逐条件出处。字段必须包括 body、head、例外、strict/defeasible、时间/辖区范围、规则来源、适用对象、条件间 AND/OR、优先依据。OR 拆成多个规则；多层条件分为明确的中间谓词。
3. 编译器检查原文 span、变量类型与安全性、未定义谓词、明确否定、优先关系环、规则依赖环、同一术语不同定义。模型最多修正一次语法；法律语义不能靠语法通过判定。
4. 专家逐项核验适用范围、遗漏条件、例外和规范强度；未核验条目标记 DRAFT，不进入自动推理。事实到要件的桥接规则也必须审阅，不能把“paid_full”直接命名为“breach”。保存人工时间，不假装这是免费的先验知识。
5. 每条规则附构造测试：全部前提存在、分别去掉一条、加入例外、改变合同/角色、改变适用时间。测试检查编译忠实性，不证明原规则在真实法律上解释正确。

```text
Rule {
  rule_id, version, body:[typed_signed_literal], head,
  kind: STRICT|DEFEASIBLE,
  scope:{jurisdiction, issue, effective_interval, stage},
  material_exceptions:[literal], exception_mode:ATTACK_ONLY|REQUIRES_NEG|UNSPECIFIED,
  exception_policy_sources[],
  priority_edges:[(stronger_rule,weaker_rule,source)],
  authority_spans[], review_status, reviewer_decisions[]
}
```

首版限定有限、无函数、range-restricted Horn 规则，body 已出现的变量才能进入 head；正向依赖为 DAG，拒绝循环规则包并交给专家改写或后续支持循环的引擎。论证攻击图允许环。这个限制保证有限构造，代价是不覆盖全部复杂法律逻辑、量化证明责任、动态义务和价值权衡。

### 5.3 来源陈述、对象事实与例外

保留两个维度：`reported_support(p)=(有支持p的合格来源, 有支持¬p的合格来源)` 可以是10、01、11、00；论证状态另为 IN/OUT/UNDEC。11是冲突，00是缺失，不能都写成unknown。这些状态不是概率。

首版采用 ASPIC+ 的一个明确受限配置。知识公理 Kn 只包含已核验的来源记录，例如“s2记载法院认定paid_full”，以及形式词典；它只保证快照里有这段记录。普通前提 Kp 设为空。对象层事实通过可废止投射规则产生，例如 `source_record(s2,FOUND,p) => p`。因此支持 p 和 ¬p 的来源都能保存，冲突发生在可攻击的投射论证上。FOUND不被当成永真事实。

ALLEGED默认只导出 `says(party,p)`；当事人视图另用带视图标记的可废止投射导出 p。法院记录视图和当事人视图分别运行和报告。事实桥接、法律规则、例外规则均可废止；strict规则只处理技术关系，不能从不可攻击的公理直接推出实质法律结论。

每个例外 E 的执行方式必须由规则审阅明确选择，而不是系统统一猜测：

| 已审阅模式 | 编译形式 | 没有 E 或 ¬E 记录时 |
|---|---|---|
| ATTACK_ONLY | 条件 ⇒ q；E ⇒ ¬applicable(r,binding) | 普通条件满足即可构造可废止论证，不生成¬E。只有有法源依据的默认适用/抗辩安排才允许这种模式 |
| REQUIRES_NEG | 条件 ∧ ¬E ⇒ q；E 可另攻击适用 | 缺少¬E就不构造该规则论证，记录缺失前提 |
| UNSPECIFIED | 例外如何影响适用尚未审阅 | 该规则保持DRAFT/BLOCKED_POLICY，其他独立规则仍可运行 |

所以“没有检索到例外”不能成为¬E的证据，但在明确允许默认适用的规则中也不必凭空增加“证明所有例外不存在”的义务。双方对E有支持时，由攻击图处理其冲突。默认适用的法源保存在规则的exception_policy_sources及每次应用的轨迹中；首版不增加独立的applicable正向谓词，以免与ASPIC+的规则命名/undercut接口混淆。所有输出标明当前规则包、事实视图和适用方式。

### 5.4 论证构造、优先与接受算法

先按时间、辖区和争点过滤规则。按规则依赖的拓扑顺序连接 body 关系，生成全部合法绑定。每个论证保存 `head, top_rule, source_ids, children, rule_version`；同一结构及来源集合去重。攻击图允许环，正向推导规则依赖为 DAG。没有模型参与最终接受状态的计算。

ASPIC+区分以下攻击。首版Kp为空，因此undermine没有实例；保留这一接口以便未来扩展，不能把不同来源记录直接删除：

- rebut：A的结论反驳B中某个可废止子论证的结论。
- undercut：A的结论是 `¬applicable(rule_id,binding)`，只攻击B中的那次可废止规则应用。
- undermine：反驳普通前提；本配置没有普通前提，事实冲突通过投射规则的rebut处理。

rebut不能直接攻击top rule为strict的技术子论证，只能通过攻击其可攻击的子论证间接影响上层。攻击子论证会攻击包含它的上层论证。undercut不受规则优先关系阻挡。rebut只有在攻击者并不严格弱于被攻击子论证时构成defeat。

规则优先关系 `>R` 由专家依据法源登记，为严格无环偏序，求传递闭包，发现环即拒绝该规则包。不能用模型信心、判决胜败或检索排名代替优先依据。首版固定last-link与严格elitist集合比较：top rule可废止时 `Last(A)={top_rule}`，否则递归取子论证最后可废止规则的并集。定义

```text
weaker(A,B) := Last(A)、Last(B)非空，且
              存在 a∈Last(A)，使每个 b∈Last(B) 都满足 b >R a
```

空Last集合不凭空弱于另一集合。没有优先边通常意味着互不更弱，而不是模型随机选边。技术strict结论与实质谓词分离，避免借空集合绕过来源投射。

```python
Args = construct_all_arguments(source_records, reviewed_rule_package)
Defeats = set()
for A in Args:
    for B in Args:
        for sub in B.subarguments:
            if undercuts(A, sub): Defeats.add((A,B))
            elif rebuts(A, sub) and not weaker(A, sub):
                Defeats.add((A,B))
IN = set()
while True:
    defended = {a for a in Args
                if all(any((c,b) in Defeats for c in IN)
                       for b in attackers(a, Defeats))}
    if defended == IN: break
    IN = defended
OUT = {a for a in Args if any((b,a) in Defeats for b in IN)}
UNDEC = Args - IN - OUT
```

grounded计算从空集逐轮加入被当前IN集合防卫的论证，在有限图上终止。OUT表示一个论证被接受论证击败，不意味着它的结论已被证明为假。命题p分别报告是否存在IN论证支持p/¬p、UNDEC论证和阻断原因。如果两边都有IN，显式报告INCONSISTENT并检查理论条件，不在未验证时宣称这种情况不可能。

事实与法律前提使用共享谓词精确匹配或经审阅桥接规则连接。桥接草稿由法源条件与A定义检索产生，要求逐个槽位、状态、辖区、时间和原文依据，机械检查类型，随后人工核验并版本化。`paid_full`不自动等于`breach`，相似度只能提出映射候选。B模式可以一次检索一组事实，但展开后仍使用原assertion IDs，不增加一份独立证据或投票权重。

### 5.5 贯穿例子的实际结果

使用以下虚构规则包：

```text
r1: agreed_delivery(K) AND due(K) AND not_delivered(K)
    AND not_extended(K) => breach_element(K)
r2: extended(K) => not_applicable(r1,K)
```

`r1` 是可废止规则；`r2` 是针对该应用的例外规则。付款只是背景事实，并不足以推出交付义务。

原始 J1 没有 due(K1)，因此 r1 因缺少前提停止；s6 的延期争议另列为缺口。B 已发现付款＋未交付模式，也不能让 r1 跳过 due 或 agreed_delivery。

变体 V1：新增明确来源支持 agreed_delivery(K1)、due(K1)、¬extended(K1)，其余无相反证据。构造 r1 论证，无攻击时该论证进入 IN，输出“这个规则包下的 breach_element 有支持”，不升级为整个请求或案件胜诉。

变体 V2：有 due 与 agreed_delivery，但延期仅有双方未解决的冲突。在当事人论证视图中，extended 与 ¬extended 的来源投射论证相互 rebut；r2 还 undercut r1，grounded 保留相关争议为 UNDEC。法院记录视图若未采纳任一方，则 E 是 unknown，r1 暂停，结果同样不能认证，但未决原因不同。

变体 V3：只有 extended 有合格支持。r2 给出例外，r1 不能据此被接受。变体 V4：若实际规则经审阅采用ATTACK_ONLY，则应发布不同的规则版本，去掉r1的¬extended前提，保留r2的例外攻击。延期未记载时可以构造可废止r1论证，不生成“未延期”的事实。新增延期来源后重算攻击图。不能在看到当前案例缺信息后临时更换例外模式以获得想要的结论。

### 5.6 成本、边界与强替代

原型每个争点最多 30 条规则、每条最多 5 个变量、每案件最多 10,000 个论证。遇到超限返回 `INCOMPLETE_ARGUMENT_GRAPH`，不得在截断攻击图上认证 IN。可以展示已有轨迹，但必须与完整求解分开。规则依赖 DAG 和有限实例保证有限性，论证组合数量仍可能指数增长；grounded 标记相对于已构造图可多项式计算，不能把它写成整个系统都便宜。

| 强替代 | 机制和具体局限 | 本方案差异 | 为什么可能有用 | 成本/失败条件 | 决定性实验 |
|---|---|---|---|---|---|
| 相同事实/法源的直接 LLM 或结构化清单 | 可解释开放文本，清单可逐条检查前提；通常没有固定的递归击败语义 | 编译规则、构造子论证攻击、固定点接受 | 多层例外与同权冲突中减少漏条件和任意选边 | 规则编译很贵，清单对简单争点可能足够 | 相同模型、资料、规则、专家时间，固定回答覆盖比较错误断言与正确解决量 |
| SPINdle/可废止逻辑引擎 | 成熟的规则、冲突和优先处理；具体 ambiguity/defeat 语义取决于配置 | 为本项目保留子论证和来源节点，选择 grounded | 直接对应所需的事实—规则—支持/反对轨迹 | 若现有引擎已有同等轨迹，计算优势不成立，优先复用 | 同规则语义的相符子集比较状态、轨迹与成本；差异来自语义时不作准确率排名 |
| 成熟 ASPIC+ 实现 | 与首选共享形式基础，不是被我们取代的弱基线 | 项目适配主要在来源桥接、例外模式、版本接口 | 降低自然语言与形式输入错配 | 实现可能不支持所选 preference lifting；要测兼容 | 同一编译 theory 上应得到相同结果；不同是实现/语义问题，不是新算法优越性 |
| ANGRY＋ASPforASPIC（KR 2025） | 用 Datalog 缩小 grounding，原文实验验证了所给无偏好框架；preferences 被列为未来工作 | 首版完整有限构造，保留本项目已审阅优先关系 | 小规则包下可直接检查完整轨迹与优先处理 | 更慢且规模小；ANGRY若适配成立应替换 grounding | 先验证输出/轨迹等价，再比内存与时间；不迁移未经证明的带优先级保证 |
| LRI / SILVER 式规则归纳或法律形式化 LLM | 学或生成规则，可减少人工起草；错误可能在符号输入前已经产生 | 自动起草后核验，固定规则包再推理 | 避免把经验关联/错误翻译当规范依据 | 人工成本可能抵消收益，覆盖有限 | 同规则审查预算下比条件/例外召回、编译正确率与下游覆盖 |

C 的条件保证是“给定有限论证图、所定义 defeat 和规则包，计算其 grounded 集合”，不是事实真实性或法律正确性的保证。若成熟引擎在相同语义下输出相同结果，就直接采用它；若清单在目标争点同等准确且总成本明显更低，就不需要完整论证构造。

## 6. 组件怎样协调

| 生产组件 | 交付对象 | 下一组件真正消费的字段 | 禁止的隐式转换 |
|---|---|---|---|
| 来源层 | SourceSpan、文书/诉讼关联快照 | source ID、原文、时间与请求范围 | JSON facts 字段自动当事实金标准 |
| A 抽取 | Assertion＋未决解释 | 明确身份、极性、状态、来源 | 缺失变否定；主张变认定；角色名变同一实体 |
| A 规范化 | TypeDefinition、membership、版本与判定缓存 | 冻结谓词 ID、实例绑定、视图筛选 | family 上位归属变等价；簇标签改写实例 |
| B | Query、Witness、unit/family support、字典 | 原子列表、共享变量、具体 assertion IDs | 频繁模式自动变法律规则；同源事实重复计权 |
| 法源编译 | ReviewedRulePackage | 适用范围、body/head、例外、优先与出处 | 经验规律变规范依据；模型分数变法律优先 |
| C | Argument、DefeatEdge、Acceptability、Gap | 来源和规则依赖、未决原因 | OUT 变命题为假；条件结论变无条件事实 |

A 的每个 mapping 保存 `source/extraction/identity/type_version`。B 另保存 `view/grammar/search/encoding_version`；C 保存 `rule_package/preference/view_version`。所有发布采用一次完整快照，不能让新类别配旧模式支持度。

A 修正后，旧成员映射、查询见证和相关论证都不能继续当当前结果。**仅追踪已存在的正向依赖不够**：新事实可能使原来被剪枝的查询变频繁，也可能成为旧论证的新攻击者。首版 A 做局部修复，B 对受影响领域全量重挖与重选字典，C 对受影响案件完整重建论证图。此规模下这样比复杂的增量维护更可靠。

同一原子多处出现只保留一个 ground atom，source 列表并集；不同陈述状态仍不同。B 的一个模式宏与构成它的事实不能给 C 多加一次权重。向 C 提供 B 的主要作用是检索和呈现常见结构，C 总能直接查询 A 中未入字典的事实；否则压缩选择会错误地删除法律前提。

开发阶段可根据原文纠正 A，但不能因为某个模式更漂亮或与 WIN/LOSE 更相关就放宽类型定义。A 类型/阈值先冻结，B 在发现集挖掘并选择后冻结，最后在独立确认集执行；确认集不能反向修定义。修订需要新版本和新的确认材料。

### 为什么组合可能比单个组件有用

EDC 式规范化可合并表达，但单独不能验证跨合同关系；WARMR 可以连接对象，但上游把 K1/K2 合成一个 ID 时仍会得到错误模式；ASPIC+ 可以执行规则，但不会自动修正错误前提。因此组合价值应分别测量：A 是否减少错误映射，B 是否减少错误绑定/冗余，C 是否减少漏条件/任意冲突裁决。

组合不会自动相加获益。完全链接拆得过细会降低 B 支持；MDL 偏好常见结构会漏掉 C 所需稀有抗辩；C 错译默认适用或举证安排会降低正确解决量。对应机制是保留原子事实直达 C、字典外保存稀有候选、分开报告缺口和判断覆盖，而不是用一个总分掩盖取舍。

## 7. 如何确认或推翻选择

算法已经明确，以下实验用于检验选择，不替代算法设计。先完成同一争点的原型，再扩大领域，不把全部 6,954 条当同质任务。

### 7.1 划分与公平条件

按诉讼组隔离开发/发现/确认材料，时间可用时增加时间隔离。可从约 1,000 个合格单元规划 20% 开发、50% 发现、30% 确认，实际比例按独立诉讼组数量和目标效应功效模拟调整；这不是保证统计功效的样本量。数据不足时仍可验证实现机制，但不报告稳定跨域规律。

所有方法获得相同原文范围、角色/状态/身份表示、专家约束和模型版本。先做 oracle-input 实验：人工核验 A 输入给 B、人工核验事实与规则给 C；再换自动 A，区分组件错误。预算同时报告 token、重试、CPU/GPU 时间、峰值内存、人工分钟与建设 schema 的成本，不只数 API 调用。

自然案件盲审和构造难例分开报告。难例用于验证已知机制，不能作为真实案件有效性的证据。固定同义改写、状态替换、合同交换、否定作用域、缺失例外、同权冲突与规则优先变化，检查预期输出；另随机抽自然案件估计现实错误。

### 7.2 各模块的决定性比较

| 模块 | 主要指标 | 必做消融 | 何时换方案 |
|---|---|---|---|
| A | 槽位/状态/绑定准确率、重要误合并率、B-cubed、同义对召回、singleton/未决率、每千事实总成本、增量版本稳定性 | 同图MILP换贪心；全簇核验换定义-only/代表/边界；保留相同schema；关闭局部修复；换约束查询策略 | MILP只改善图目标但不改善正确复用，退回同图贪心；完全准入在等预算等覆盖下未减少重要误合并，或只靠大量singleton获得低错误，改用原PDF代表核验/软约束 |
| B | witness 正确率、有效非冗余模式/专家小时、unit/family覆盖、确认集支持变化、描述长度、候选和匹配成本 | 同候选同编码下MILP换贪心；换 top-k、最大覆盖、SLIM/Snor式选择；同表示下换gSpan；固定关系特征＋FP；去绑定/去状态仅作机制诊断 | 约束搜索漏掉重要模式而不省成本，换gSpan/KG-MDL；压缩只改善位数却降低专家效用，换最大覆盖或简单去重 |
| C | 规则条件/例外召回、grounding准确率、错误认证率、正确解决量、缺口定位准确率、轨迹可复核性、专家总时间 | 同规则下直接LLM/清单/成熟引擎；固定规则下比较例外模式的编译忠实性；去优先关系；有无B；人工/自动规则分开 | 清单在匹配覆盖下同样好且更便宜，使用清单；成熟引擎同语义更快，复用引擎；规则编译错误主导则先改编译 |

全拒答系统和全 singleton 系统不得因零错误获胜。预先报告错误—覆盖—成本曲线，在相同覆盖附近比较错误，在相同预算下比较正确产出，并设最低复用/覆盖约束。没有配置满足约束就是失败结果。

B 的无标签确认只验证“相同查询能否在独立材料再次找到正确见证”，不证明因果、法律效力或预测增益。未来加入已核验的请求级结果后，预先冻结模式与比较组，用带分组相关性处理的效应估计检验关联；不能把 NO_RECORDED_WITNESS 当真实否定，也不能在同一批数据挑模式再只校正最后几条的 p 值。

| 主张类别 | 可以说什么 | 不能说什么 |
|---|---|---|

### 7.4 已实际运行的小型检查

本次自行编写并运行同目录《机制样例.py》，结果见《机制样例结果.json》。A穷举64个四节点无向图及其可行划分，核对完整正向准入和最优目标不差于固定贪心。B检查状态/合同绑定，并穷举一个三单元合成覆盖问题，检查全部事实可由模式展开和剩余原子重建。C对包括自攻击的全部512个三论证有向图计算grounded集合，与独立枚举complete extensions后的交集比较。

这些检查全部通过，范围很有限：A未测试语言判断，B使用假设成本和符号展开，尚未实现二进制编码器或大规模查询搜索；C只测试抽象论证图，尚未测试完整ASPIC+构造与法律编译。因此它们支持说明中的小型计算，没有产生真实法律案件准确率、生产MILP性能或端到端收益。

## 8. 首版实现顺序

1. 建共同数据结构、来源和局部身份表。先以已审查的小样本跑通 A 的检索、成对判断缓存、完整准入、分量优化和拆分；同时实现完整 PDF 代表核验基线。
2. 对冻结事实实现 B 的有限查询生成、连接见证和两种支持计数。先用独立小图穷举对照验证搜索与剪枝，再接字典编码器与集合覆盖MILP，必须验证解码重建与原事实集合完全一致。
3. 对一个争点建立经审阅规则包，实现 C 的编译检查、来源投射、例外模式、攻击/击败、grounded 标记和依赖轨迹。先用确定语义样例验证，再接模型起草。
4. 运行模块比较和误差传播实验，再决定是否扩大领域、采用更高效引擎或研究新的复核策略。

目前已经选择的是可执行机制，不是新的专有算法名。潜在论文贡献需要来自这些机制在真实法律材料中的可测收益，或者一个超出现有方法的实质性改进。若公平比较发现现有算法已经足够，就保留现有算法。
