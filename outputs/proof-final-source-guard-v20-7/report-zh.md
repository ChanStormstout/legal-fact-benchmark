# V20.7 修复与缓存验收

2026-10-13。三类问题的工程修复已实现于独立入口：解除摘要和正文误加的 480 字符限制，限制最终论据只能选择来源已核验且依赖有效的声明，增加人物、物业、事件主体和法院阶段检查，并要求对具体最终答案完成来源与完整性核验。主线程入口和旧结果保留，没有生成、网页提交、训练、提交或推送。

## 已确认的原因与实现

摘要截断的直接原因是正文和辅助说明共享字符串 schema。对辅助文字增加上限时，上限扩散到了摘要和正文。新版本逐个复制字段规则，只限制辅助说明；612 字符的合成摘要通过真实 tokenizer/约束器逐 token 回放与最终入口，未被裁剪。

中间被排除事实能够重新进入答案，是因为旧写作允许重新解释完整原文，而最终入口仅检查格式和引用编号。新入口保存完整原文、原始候选和核验记录，自动选择材料只保留已核验且依赖有效的声明；实际案件的 assumptions 必须为空。新增事实需先补声明核验，最终每一个文字字段及整案覆盖还必须核对原文。没有核验、核验未决或核验失败均返回 null 答案。

主体错配和遗漏能够被放行，是因为旧入口不检查当事人、物业、行为主体或法院阶段。新结构保存这些信息，程序检查类别和关联冲突，具体名称、事件和程序层级由最终来源核验确认。另外修复了同一前提的多个 J:n 共用首条审计状态的问题。模型为何首次产生这些错读，尚未确认唯一原因；此次工程修复不能保证模型不再提出错误答案。

## 验证证据

34 项新回归测试、5 项已有来源修复测试、18 项既有核验接口测试全部通过，共 57 项。测试覆盖正文超过 480 字符、辅助字段仍受控、被排除声明与依赖不被选择、假设旁路、条件付款与争议日期、申请人与法院错配、发回法院错配、人物物业缺项、重要反驳遗漏、半句话、核验内容过期、核验缺项和重复 JSON 字段。语义标签注入仅验证程序会按核验结果拦截，不评价模型判断的准确率。

真实缓存经原来源核验应用、合并与独立检查，再进入新最终任务入口，结果如下。

1954254 的 138 个段落和 569555 的 353 个段落完整保存在新来源文件并进入输入；空白段仅不作为证据选项。372 条可选声明的内容逐项与应用池比对一致，短编号和依赖能完整恢复；其余 82 条声明仍可从应用文件和原核验记录读取。全部 454 条声明均有去向，没有静默丢弃。

唯一现有的 1954254 最终答案通过实际 `accept` 命令重放，因不符合新合同被拒绝，原 480 字符摘要和原始回复保持原样。这是入口行为验证，不能当作新模型答案通过了内容验收。

证据位于 `validated-01/engineering/cache-integrity.json`、`tokenizer-and-entry.json`、`legacy-cli-accept/acceptance.json` 和 `task-tokens.json`；当前冻结协议为 `validated-01/freeze/protocol.json`。根目录初次准备与冻结副本也保留，没有覆盖为最终版本。

## 尚未验收的部分

三案均没有通过新版本的完整答案验收，真实模型最终答案尚未重跑。1954254 仍保留旧失败答案；569555 只完成已保存核对结果的应用；1187427 仍缺少取回的核对结果。具体答案的来源核验器仍可能误读原文，不是人工金标准或法律批准。

本地 tokenizer 估算两案输入为 92,764 和 86,878 tokens，预留输出后为 109,148 和 103,262，均不适用于原本地 65,536 预算。估算低于旧服务记录的 262,144 上下文，尚未验证当前服务包装、实时容量或可用性。新入口未删减原文，也未启动真实调用。

修复前快照覆盖的 2,166 个旧文件哈希均保持，包括旧代码、四个历史结果目录、README、PROJECT_STATE 和主审阅入口。冻结验证通过。没有恢复旧队列、修改主模型入口、训练、提交或推送。
