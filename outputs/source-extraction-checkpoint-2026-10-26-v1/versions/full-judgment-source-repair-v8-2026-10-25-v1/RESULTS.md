The old empty-record/nonexistent-index fatal error did not recur: record addresses now originate in the program. The repaired comparator did not generate the forbidden DECIDED_BY relation. Its native canonicalizer still dropped two other invalid endpoint/relation combinations, which remain recorded. Thus the repair removed the earlier fatal schema error, not every graph-generation error.

In batch-003/R0012, the partition allegation was correctly attributed to Defendant 1, with Defendant 2 described as the alleged recipient; source L130 and its context L129 support this distinction. This is a real localized improvement over earlier misattribution, not a completed-case accuracy result.

The addressed revision path changed some actual records and retained the originals. One example is batch-004/R0000.r0, which changes a record to DENIAL. Proposed revisions are not silently treated as independently checked facts.

## Remaining observed failures

1. **Repetition and source granularity.** Although calls were grouped, V8 still requested a record container for each physical source entry. In batch-001, a single wrapped headnote sentence was repeated across numerous entries. Grouping calls did not remove the per-line output incentive. This is a design/interface limitation, not solely a model-capacity claim.
2. **Generated quotations.** The model combined text from multiple entries into a purported quote for one source ID, or normalized source characters. Literal checking prevented unsupported admission, but 55 of the 122 retained records in completed batches still had nonliteral witnesses. Quarantine is not a correction. The mismatch between wrapped source fragments and model-retyped quotes is avoidable interface burden.
3. **Redundant review decisions.** There were 28 records whose six component checks all said SUPPORTED while the final decision said UNRESOLVED. The consumer retained uncertainty instead of accepting the contradiction. Other proposals requested replacements without an identified error or repeated the original. The separate component vector and final decision created unnecessary inconsistency opportunities.
4. **Metadata omissions.** Batch-000 classified the named court, parties, date and citations as NO_CONTENT despite explicit extraction instructions; review added nothing. These are omissions, not successfully extracted metadata.
5. **Meaning remains fallible.** Batch-002/R0014 incorrectly represented the headnote's treatment as Balmukund dissenting from Banee Prasad; the text instead reports the current court's treatment of those authorities. Batch-005/R0003 rendered an open question about leasing power as a positive legal argument. These records were unresolved, but the reading errors remain.
6. **Comparator status conflation.** Its final graph still labels the lease-grant event, actual possession, and absence of an ordinary-management plea as court_status=REJECTED. The semantic reviewer received these fields but passed their narrative descriptions without correcting the statuses. Prompt1A also invented 'Panchanamas (implied by context of possession disputes)' and an additional Court-of-Wards/Appellee party. Generic cautionary prompts did not eliminate these errors.

Completed V8 batches retain 122 records: 96 UNRESOLVED, 24 MODEL_REVIEW_SUPPORTED and 2 REVISION_NOT_INDEPENDENTLY_REVIEWED. These are internal state counts, not accuracy scores. Each interpretation still requires source review. The complete record inventory and measurements are in private/evaluation-v1. No human gold or independent legal validation is claimed.
