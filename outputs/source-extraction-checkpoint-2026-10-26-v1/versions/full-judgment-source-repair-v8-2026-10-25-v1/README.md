# Full-judgment source extraction repair V8

This isolated experiment repairs source-reading interfaces exposed by the preceding full-judgment attempt. It is not a completed RAPIDO C integration, an A0 experiment, or a new held-out benchmark. Only case 1251841 is authorized. Both arms receive the identical 139 rendered source entries, including the judgment outcome. Website navigation is excluded; no judgment content is shortened.

## Repairs and evidence boundaries

| Observed problem | Implemented change | Remaining uncertainty |
| --- | --- | --- |
| Empty records with nonexistent record index zero halted V7 | Records nested under program-provided source keys; no model-authored indexes; mutually exclusive empty/nonempty schema branches | A model can still omit or misinterpret substantive content |
| Court and party metadata treated as empty layout | Metadata is an explicit record kind; only empty headings/layout can be NO_CONTENT | Correct attribution still needs model reading |
| Tiny wrapped entries caused many calls | Consecutive length-based groups, all full sources in every call, no clipping | Cross-boundary antecedents still require correct reading |
| Event occurrence confused with legal force | Separate proposition layer and attributed record kind; scope and conditions stored with the proposition | Representation alone cannot guarantee correct classification |
| Conditions and burdens omitted | Explicit qualification records and quoted witnesses; review audits lexical cues without treating cues as truth | Implicit conditions may still be missed |
| Matching wrong IDs falsely accepted | Program-owned record addresses and immutable review snapshot; source quotations checked literally | A real quote can support a wrong interpretation |
| Revision failed to change erroneous content | Addressed REPLACE/WITHDRAW plus source-row additions actually update active records; original and retired records retained | Corrected/additional records remain explicitly not independently reviewed |
| Native comparator emitted forbidden DECIDED_BY relation | Separate repaired local adapter constrains generation to the existing native candidate contract and source IDs, retains native validation | Valid relations can still be semantically wrong; native canonicalizer removals remain visible |

The repaired LatentWeaver adaptation is explicitly distinct from pinned upstream commit 156a0c32275682421bc0746678749e20a318debf and from the preceding unchanged same-model adaptation. Generic source-fidelity prompt guidance is added; no case answer or review reference is sent to either arm. The upstream native model differs from the shared Qwen 9B, so these are not claims about native upstream performance.

## Execution and accounting

`execute.py` uses the existing authorized credential and transport without displaying credentials, the shared nonblocking API lock, identical Qwen parameters, explicit 65,536-token output capacity, and error-on-context-overflow. ## Acceptance

Offline acceptance checked full-source transport, lossless grouping, equivalent generated/consumed schemas, program-owned addresses, source-quoted revision, stale-snapshot rejection, condition preservation, and forbidden native relation rejection. A mock complete reading/review chain is an engineering fixture, not a model result. The native/compiled candidate conditional branches were compared, and the graph fixture with edges removed was independently confirmed valid under the compiled contract. None of these checks establish model accuracy.

Real validation will inspect final records against the original document, preserving distinctions between current and lower court, party assertions and findings, occurrence and effect, qualifications and unsupported evidence. Reference review is a source-grounded model/agent assessment, not independent human gold. All empty or failed outputs remain failures; null semantic quality is not converted to zero accuracy or success. Old excerpts, previous full-document results, and patched results must not be pooled as one experiment.
