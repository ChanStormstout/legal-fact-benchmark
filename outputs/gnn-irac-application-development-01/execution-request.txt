**我的结论是：现在需要调整的已经不是某个标签或某个门槛，而是实验的基本单位和推进方式。我们应该从“先构造若干整案完整、完全通过审阅的IRAC链，才允许训练”，改成“以具体法律问题及其条件为单位，保留可用的部分监督，同时开始实现和运行模型”。**

但不能简单把所有限制放开。**输入泄漏、任务混淆和错误标签必须继续控制；整案必须完整、必须凑够某个数量、开发阶段不许修改、必须先接上组内全部上游，这些不应该再成为统一的停工条件。** 我之前给出的部分规定，把阶段性成本控制变成了近乎永久的科研前提，需要修正。

## 一、除了范围太窄，还存在六个更深的问题

### 1. 我们把三个不同的问题，混成了一个“IRAC是否成功”

现在至少存在三种任务：

**第一种是还原裁判：**这家法院实际上怎样处理了某个条件？答案应来自它的裁判理由。

**第二种是基于给定材料进行法律分析：**仅看这些材料，某个条件是否已得到支持？答案可能与历史法院的结果不同，因为历史法院可能看过我们没有的证据。

**第三种是预测最终诉讼结果：**法院会不会支持请求、撤销原判或发回重审？这还涉及程序、审查标准和其他请求。

当前数据有时让模型预测第一种，却用第二种解释错误，再拿第三种结果证明第一种标签成立。最明显的是 `targets/1497837.json`：六个实体条件都因目标法院未独立裁判而记为 `UNRESOLVED/NOT_DECIDED`，同时 `issue_target=SUPPORTED` 表示程序性恢复下级结果。这个记录可以忠实描述历史，但**不能把它直接放进“实体条件→实体结论”的统一训练任务**。

**新方案必须先固定预测对象：给定某次裁判之前的允许材料，以及明确给定的法律标准，预测该次裁判对一个具体条件作出的实体判断。** 程序性结果另存，不当成同一个输出。

### 2. `UNRESOLVED` 里混进了“不知道答案”和“法院没有回答”

这是比单纯噪声更严重的标签问题。

“法院认真审查后认为现有证据无法确定某条件”和“法院因为只处理程序问题，根本没有讨论该条件”不是一回事。前者可能是有意义的第三类监督；后者通常只是**这个训练目标没有被观察到**。

现在 `1497837` 的六条 `NOT_DECIDED` 被保存为六条 `UNRESOLVED`。若直接训练，模型可能学到的是“这类上诉一般不重新认定事实”，而不是“这些事实如何适用法律”。

因此，上一条回复中我说“C3是UNRESOLVED就可以进入loss”仍不够准确。**必须先判断这个未决状态本身有没有明确监督依据。未被裁判、未标注、审阅者拿不准，都不能自动成为第三类标签。**

### 3. 当前门槛在代码里确实把局部问题放大成整案失败

`irac02_freeze_rules.py` 将所有规则、条件及引用检查汇总成一个 `complete`。其中任何一项触发阻断，整个案件的盲输入便成为 `None`，跳过全部连接生成。`irac02_finish.py` 又会因为任一目标引文定位错误，把整案设为GAP。 

这适合验收“整条完整链”，却不适合当前的**条件级学习**。一个案件有四个条件，其中两个有可靠规则、事实和目标，不应因第三个缺标签而全部丢弃。

不过，部分监督也不是简单加一个mask就万事大吉。**mask只控制哪些输出进入损失，不能阻止错误输入在图中传播。** 如果一个节点包含目标答案，或一个错误规则通过边影响其他条件，屏蔽它的标签并不能消除问题。必须先保证输入安全，再对监督做局部屏蔽。

### 4. 我们让一个看不到案件事实的审阅任务，判断“本案决定性规则是否完整”

`irac02_review_rules.py` 明确不给审阅者事实、目标和绑定，却要求它判定 `rule_complete`、发现缺失的决定性测试；最后的完整链审阅则能看完整案件与目标材料。

所以，前后意见不同，**不能全部解释为“模型审阅不稳定”**。两次任务的信息和实际问题不同：前者适合判断“条件是否忠实于所给规则”，后者才有条件判断“这些规则是否覆盖本案重要问题”。

以后应分开：

> **规则忠实性：**这个条件是否忠实表达法源？  
> **案件覆盖：**当前数据支持分析哪些条件，还缺哪些？

规则忠实性不通过，隔离相应条件；案件覆盖不完整，限制本案可回答范围。不要再把二者合成一个全案开关。

### 5. “每案重新拆规则”既增加费用，也制造跨案不一致

当前 `irac02_rules.py` 为每案配置法源包，再独立产生最多八个条件。相似规则在不同案中可能被分成不同的条件、依赖和极性。

这样，GNN面对的不只是事实变化，还有上游对同一规则的表达变化。新的做法应是**复用有版本、有范围的规则模板**。

但不能把“一个claim family”误当成“一套永远相同的规则”。模板至少要区分法域、法条版本、请求类型和重要例外；同一名称下的不同法律测试不能强行合并。我们要减少重复拆解，不是抹掉法律差异。

### 6. 上游已经做了多少推理，需要成为实验定义，而不是被忽略

目前盲绑定会输出 `SUPPORTS/DEFEATS/RELEVANT_TO`。代码确实限制了它不能引用新事实、不能改变陈述状态，并排除了目标字段；这是有价值的工作。**这种输入并不因为有方向就必然泄漏。**

但它已经提供了部分法律判断。GNN最后可能主要是在汇总High提出的支持／反对意见。这个任务可以研究，只是不能声称GNN独立完成了全部事实适用。

我也要修正上一条过强的建议：**不是必须禁止所有signed bindings，而是先明确主实验要测什么。** 我的首选是主实验不依赖逐案LLM判断支持方向，直接使用事实关系和无方向的条件候选连接。这样既减少一轮标注，也减少“上游替GNN做了主要判断”的混杂。

## 二、还有几项应当解除，但不能矫枉过正

**法律范围可以扩大，法院层级不应成为硬门槛。** 不再只收§14(1)(b)，也不自动认定最高法院案件都不适合。真正的入选依据应是：文书里是否存在与本任务相符、可定位的实体适用判断。规则来源与训练案例来源可以不同。

**旧开发案不是必须永远禁止复用。** 不改历史结果，不等于不能把其中有用的来源、事实或明确判断作为新版本的训练开发资源。它们不能转成独立测试，但也不必全部推倒重来。原来的“旧八案永远不再碰”应理解为“不再专门花一轮把八案修到全案READY”，不是“已有有效记录从此不得使用”。

**候选预算应控制投入，而非制造样本整齐性。** “16案中不足6案就一条也不构建”没有提供必要的科学保障。以后每个合格的数据单元都能推进，达到预算就交付实际产出，不补造数量。

**组内canonical和pattern mining都不是本地模型开发的前置条件。** 当前接口审计已经指出组内canonical不直接包含Rule、Condition和Application节点，真实八案产物也没有接入。因此应维护适配接口，但不能继续等到上游全部齐全才写模型。

**不能把选案失败说成整个语料库“召回率太差”或“没有数据”。** 你贴出的16案筛查显示的是这批定位规则的合格产出率低；没有完整合格集合，就还没有测出召回率。

最需要继续坚持的是：目标结果不能进入输入；未证明不等于事实为假；同一纠纷不得跨训练与测试；来源、程序阶段和真实未知必须保留。其他规定应服务于这些底线，而不是与它们享有同等的停工权。

## 三、新研究设计：以“裁判问题—条件”为单位，而不是整案通过验收

我建议把下一阶段正式定义为：

> **在给定法律标准、相同允许事实和关系记录的情况下，关系消息传递能否改善对具体法律条件裁判状态的预测？**

这是一个**回顾性的、给定规则的条件适用任务**。它不测试自动找法，也不直接预测整件诉讼胜负。

### 1. 数据单位

一个样本由下列信息唯一确定：

```text
纠纷ID + 裁判阶段 + 请求/争点ID + 规则版本 + 条件ID
```

一个判决可以贡献多个条件，但它们仍属于同一个案件组，不能当成彼此独立的样本。一个案件也可以有几个争点；分组、损失和评价需要避免长判决因条件多而获得不成比例的权重。

目标法院不必永远是最高法院。可以把一个有详细实体分析的ARC裁判作为目标，也可以把高院明确讨论的某个实体问题作为目标。**一旦目标阶段改变，输入时间边界也必须重新定义**，不能把该阶段已经作出的认定继续放在输入里。

### 2. 标签与“是否参与训练”分开

继续保留三个模型输出，不需要扩成十几类。但另设不进入模型输入的监督mask：

| 来源实际支持的情况 | 模型目标 | 进入损失 |
|---|---|---|
| 目标裁判明确认为该条件成立 | `SATISFIED` | 是 |
| 明确认定该法律要求不成立或未获证明 | `DEFEATED`，保留具体依据类型 | 是 |
| 明确分析后认为现有记录不足以确定该条件 | `UNRESOLVED` | 是 |
| 法院没有讨论、明确不必决定该条件 | 无目标，保留`NOT_DECIDED`记录 | 否 |
| 标签提议分歧、来源不足、引用失败 | 无确定目标 | 否 |

这里的 `DEFEATED` 指**该法律条件未被确立**，不是自动宣称某个事实为假。`basis_kind`继续区分相反事实、证明责任未完成等原因。

对于“明确采纳下级判断”的情况，不必要求目标法院重新取证才允许标注；有明确采纳依据，可以记录为目标层级的采纳。但单纯恢复原判、驳回上诉，不能自动给全部条件赋值。

**监督mask不能作为输入特征，也不能决定图里哪些条件节点存在。** 否则模型可能从“哪些条件被保留”反推目标法院讨论了什么。

### 3. 输入完整性与标签完整性分开

每个可训练条件至少需要：意义清楚的条件、范围兼容的法源、与该问题相关且允许使用的材料，以及有来源的裁判目标。其他条件缺目标不影响它。

但如果某条件的历史判断依赖一份我们根本没取得内容的关键文件，就不能把“文件曾提交”当成充分输入，再强行要求模型复现法院判断。该条件保留为输入不足、暂不进入主监督；同案其他有足够材料的条件仍可使用。

这是一种**局部准入**，不是放松法律依据要求。

## 四、完整数据流程：有限扩展、多条款、复用已有资源

### 1. 先做轻量盘点，不做一个新的全量标注项目

用原数据库已有的 `issues`、事实摘要、理由、先例分析和结论字段，生成租赁／相邻财产请求的候选目录。程序先完成条款归一化、纠纷去重和已有暴露记录关联；模型只审少量候选的实际问题。

V09的活跃定位代码确实把大部分最终理由字段排除在候选处理之外，并且主要用法名与行为词匹配。这保护了输入，但也限制了发现适合监督的案件。**用于候选发现和构造训练目标，可以利用历史理由；不能因为它们禁止进入输入，就禁止一切复用。**

优先考察两至三个实际有材料支持的claim families，不预先规定必须五个。可以是不同租赁请求，也可以是相邻财产争点；具体选择由原文确认，不预设哪个family一定样本丰富。法域和法律版本分别保存，不能只因名称相似混成同一规则。

这轮建议**最多详查48份候选，目标构建约24个裁判问题包**。这是工作预算，不是24个才准训练。每个问题包有一两个可监督条件，就能贡献数据；只找到两个family也照样完成本轮，不再为了满足第三个family停工。

### 2. 为每个family建立一份可复用的规则模板

每个模板来自独立法律原文，保存法域、版本、适用范围、条件命题、必要／择一／例外关系及出处。规则审阅只负责忠实性和范围，不再承诺“已经包括每个案件全部决定性问题”。

模板中的条件尽量表达单一命题，并明确极性。例如“存在有效同意”与“不存在所需同意”不能在不同案中共用同一个ID却方向相反。证明责任触发条件、参考因素和必要条件也不能都当成同一种AND节点。

某案出现模板未覆盖的新解释，优先保留该局部缺口；开发阶段可以依据独立法源补充一个有版本的共同模板，但必须对受影响的开发数据统一处理，不能为了某个预测错误特制条件。

**“规则已给定”是实验假设，不要求先建成覆盖整个法律领域的规则库。** 法源身份可以由历史理由帮助定位，但给定规则的文字和条件不能携带目标案件的事实适用结论。

### 3. 分别构建输入与目标，不再逐案要求多轮支持方向标注

输入任务只读批准的案情片段与规则模板，产生事实、证据记录、实体、事件、关系和陈述状态。目标任务另读裁判理由，生成条件级目标、依据与mask。二者分别保存；目标构造者可以审查输入是否缺少关键材料，但不能直接补入“法院已经认定X”作为输入事实。

引用改成原生多跨度结构：

```json
{
  "source_refs": [
    {"source_id": "p12", "quote": "第一处连续原文"},
    {"source_id": "p19", "quote": "第二处连续原文"}
  ]
}
```

混合段落允许通过**有原始字符位置的子跨度**分离，而不是整段只要夹杂目标评价就全部删除；无法可靠分离的部分才隔离。对象属性也按来源处理，不要求一个对象所有属性都安全才保留其身份。禁止猜身份或把不同对象合并。

这个变化有明确依据：当前 `admit_record()` 要求整条记录的所有引用均通过阶段许可；后续又独立保留事实、对象和关系，可能留下指向被删除对象的记录。新版本应在输入构建时处理依赖闭包，而不是等最终审阅才发现悬空引用。

### 4. 现有数据如何复用

旧27案及已阅读候选保留为开发／训练资源，不得冒充新测试。已经有足够来源的事实、规则和标签可以按新接口迁移；不必重新生成所有内容。旧八案保持历史NO_GO结果，但其中来源明确的局部记录不必永久作废。

另一方面，不能把旧 `UNRESOLVED` 全部自动导入新第三类；需要按其 `basis_kind` 进行明确迁移，`NOT_DECIDED`默认不参与主损失。

输入与目标都只做一次集中来源审阅。开发期发现通用格式错误可以确定性修正；语义问题允许一次有理由的版本化处理，仍不明确的mask，不再连续召唤审阅者直到意见一致。

## 五、GNN到底怎样实现：先做能回答问题的最小模型

### 1. 输入图不再依赖High先判“支持还是反对”

图节点保留Issue、Rule、Condition、Fact、Evidence、Entity。显式来源关系包括“谁提出该事实”“事实涉及谁或哪处标的”“证据记录关联哪项事实”“规则包含哪个条件”。

对同一问题包内的事实与条件，第一版直接建立**无方向的候选连接**，不先让High逐案决定 `SUPPORTS/DEFEATS`。数据量小时可以连接该问题包全部事实与条件，不急着做top-k筛选。候选边只是允许模型关注二者，必须标明是程序生成的计算关系，不冒充来源证明。

这有两个好处：省去一轮盲绑定准备调用；上游没选到某条连接时，不会永久禁止模型使用那条事实。已有signed bindings留作历史诊断，不必删除，也不进入首版主实验。

### 2. 不再只靠32维词袋哈希理解条件和事实

当前排序图的 `hashtext()` 把文本压成32维带符号词项哈希。它作为早期轻量输入可以理解，但新任务依赖否定、角色和法律命题，这个表示不应被当作不能改变的遗产。

建议固定一个小型英文文本编码器，例如 `intfloat/e5-small-v2`，只编码和缓存，不微调。其公开模型卡给出的向量维度为384，文本长度上限为512 tokens；超长节点按已保存的句段切分，不能静默截断决定性限定。用于分类特征时按模型卡的输入前缀要求处理，两种受测模型共用同一缓存。它不是法律正确性模型，也不保证理解全部法律细节。[Hugging Face](https://huggingface.co/intfloat/e5-small-v2)

编码可以在本地单独进程完成，保存NumPy数组；小模型训练继续沿用MLX，不需要更换整套框架。模型revision、tokenizer和预处理在训练前固定。

### 3. 主比较保留三个对象，但不重演原S/B/C的不对称

| 对象 | 获得的信息 | 作用 |
|---|---|---|
| **条件先验P** | 训练数据中该规则／条件的类别频率，不读案件事实 | 检查是否仍能主要靠模板倾向完成任务 |
| **Flat：关系记录集合模型** | 相同节点文本、状态，以及相同有向关系三元组，但不逐层沿图传播 | 实用的同信息非消息传递基线 |
| **Graph：R-GCN** | 与Flat相同记录，再使用关系邻接进行消息传递 | 检查传播是否带来额外收益 |

Flat不能只拿几个统计数字，而Graph读取完整文本。具体可将每条关系编码成“起点表示＋关系类型＋终点表示”，再由目标Condition查询相关节点和关系，汇总后分类。集合汇总采用顺序不敏感的结构，思路与Deep Sets一致。[arXiv](https://arxiv.org/abs/1703.06114)

Graph使用两层R-GCN，隐藏维度64、四个基矩阵、关系方向分别编码，再使用相同的条件查询与分类头。R-GCN按关系类型进行不同变换，是它适合此处的机制；原论文并没有证明它天然能执行法律逻辑。[arXiv](https://arxiv.org/abs/1703.06103)

两者共用文本编码器、输入记录、状态字段、预测条件和训练目标，参数规模保持同一量级。**Flat也拿到关系记录，差别主要是是否进行邻居消息传播，而不是有没有被提供关系信息。** 这仍不是数学上完全纯净的机制证明，但比原来的线性18维特征对文本图网络更有解释力。

### 4. 首先预测条件，不强迫同时学习整案结论

每个Condition输出三类概率。对于标签有效的条件，损失为：

\[
L=\frac{1}{|\mathcal C|}
\sum_{c\in\mathcal C}
\frac{1}{|M_c|}
\sum_{i\in M_c}
\operatorname{CE}\!\left(\hat p_{ci},y_{ci}\right)
\]

其中 \(M_c\) 是案件 \(c\) 中有可用监督的条件集合。没有监督的条件不进入损失，但它的合法输入信息不必因此被删除。MLX已有返回逐项损失的交叉熵接口，可以据此实现mask和按案平均。[ML Explore](https://ml-explore.github.io/mlx/build/html/python/nn/_autosummary_functions/mlx.nn.losses.cross_entropy.html)

Issue-level结论只在规则组合已经明确、没有未覆盖的重要例外时，使用透明组合得到辅助结果。不要普遍套用“任何一个条件不成立就输”：不同请求可能存在择一路径、抗辩、证明责任和程序条件。**组合规则未充分形式化时就不输出自动Issue结论，仍可以完成条件预测实验。**

## 六、完整实验怎么做：模型开发立即启动，数据不用等到全案READY

### 1. 现在就运行工程训练，不需要任何真实案件数量门槛

利用两个或几个明确标为合成的图，测试数据加载、批处理、条件输出、mask、梯度和参数更新。只验证实现，不报告法律能力，也不需要为了它等待“2–4个READY案件”。

工程测试同时覆盖：改变目标不改变输入图；无标签条件不会产生损失；不同案件图之间没有消息传播；目标字段和审阅置信度不进入特征；实体ID重排不改变模型含义。

**这项工作应该和数据准备并行，并且本轮必须交付一次真实的优化器运行记录。** 不再出现“图构建器写完，但直到所有数据齐全仍不允许一次backward”的情况。

### 2. 第一轮实证比较定位为约24案的开发实验

取得多少合格条件就使用多少，不要求24案全部完整，也不要求每案恰好四个条件。规划目标是两至三个family、约24个裁判问题包；同时统计独立纠纷数量、可监督条件数量和类别分布，不能用“100条element标签”掩盖只有少数纠纷。

采用**按纠纷分组的三折开发评价**。每折的留出案件不用于拟合、标准化或早停；早停只使用该折训练部分内部预先分出的验证组。Flat与Graph使用三个预定种子，共18次小模型拟合；条件先验只从对应训练折计算。

这是一轮自动执行的交叉验证，不是18个临时小实验。全过程禁止看完某折表现后改标签、模板或特征，再继续声称是同一轮结果。

建议初始配置如下，它们是新任务的固定起点，不是最优性主张：

| 配置 | 初始值 |
|---|---|
| 文本编码器 | 冻结E5-small-v2，缓存向量 |
| 隐藏维度 | 64 |
| Graph传播层数 | 2 |
| R-GCN基矩阵 | 4 |
| Dropout | 0.1 |
| 优化器 | AdamW |
| 学习率／weight decay | \(10^{-3}\)／\(10^{-4}\) |
| 每批 | 4个问题包，保持案件组边界 |
| 训练上限 | 100 epochs |
| 早停 | 内部验证损失连续10轮无改善 |
| 随机种子 | 固定3个，全部报告 |

AdamW在MLX中已有实现；使用它是为了给新任务采用清楚的优化与正则配置，不是借换优化器“救”旧排序实验。旧S/B/C结果继续冻结，不重算成新模型成绩。[ML Explore](https://ml-explore.github.io/mlx/build/html/python/optimizers/_autosummary/mlx.optimizers.AdamW.html)

如果最终只有较少案件，仍交付可运行训练和有明确范围的开发结果，但不宣称稳定泛化；如果真实监督只剩单一类别，应报告任务缺乏判别信号，而不是人为补负例或拿训练拟合证明成功。

### 3. 数据准备预算与模型预算分开

为了避免重新展开一百轮任务，建议第一批预算如下：

| 工作 | 规划上限 |
|---|---:|
| 最多48候选的集中筛查 | 12次High |
| 最多3个family的规则模板与来源核对 | 6次High |
| 最多24案的输入准备 | 12次High |
| 对应目标准备 | 12次High |
| 集中来源审阅 | 6次High |
| 一次开发期通用修复及技术备用 | 最多8次High |
| **合计** | **最多56次High，不要求用满** |

这是按照两案输入／目标任务、四案审阅批次规划的预算；实际装包必须先检查文本量，不能为了满足次数截掉来源。复用已有有效记录可以减少调用。预算耗尽就冻结实际产出，**不再自动追加下一批候选，也不因少于某个整案数量让已有数据完全不进入训练。**

一次开发修复可以改通用引用组织、阶段解析或标签映射；无法依据来源解决的语义分歧继续mask。不能把备用调用用于“问到审阅者说READY”。

## 七、评价、错误分析和停止决定

### 1. 不只看accuracy，也不把模型解释当证明

主要报告条件级宏平均F1、每类召回、按案件平均的正确比例、概率损失，以及不同family和裁判阶段的结果。同时报告**监督覆盖率**：计划预测多少条件，真正有目标的多少，为什么其余被mask。否则只评价最容易标注的少数条件，会给出误导性的高分。

三个种子分别保留，再汇总跨种子波动。置信区间以纠纷组重采样，不以条件为独立单位。在约24案规模上，不应靠一个显著性数字下结论。

Case study只做一次集中分析：预先固定少量案例，再加入模型分歧最大的有限案例，检查规则、输入、对象连接、预测及目标依据。它能够定位具体错误；但“某条边看起来重要”不自动证明模型因那条边得出结论，注意力权重也不是法律解释认证。

### 2. 预先允许几种不同结论

**Flat明显超过条件先验，而Graph没有进一步改善：**案件材料确有开发信号，但当前消息传播不值得增加成本，保留Flat。

**Graph在多个案件和预定种子上优于Flat，且不是只靠一种family或多数类：**保留当前图模型进入独立评价。不能立即说它掌握了普遍法律推理。

**两者都接近先验：**先检查标签是否主要由条件模板身份决定、任务中是否有足够相反事实变化；本轮结束，不自动改网络。

**模型能很好拟合训练，但留出表现差：**可能有样本不足、分布变化、弱标签噪声或表示问题。报告这些证据，不再从一次开发结果宣布GNN普遍无效。

**主要错误来自历史法院使用了输入里没有的关键材料：**这是任务输入问题，不应继续用它评价模型适用能力；受影响条件从未来主评价范围中明确区分，但本轮结果保留，不悄悄修分数。

### 3. 真正封存测试放在开发设计稳定之后

现有八案SEALED继续不读。它们不需要因为换任务就自动作废，但也不能自动代表多个新family；只有另行授权、方法冻结后，才能判断其是否适合新任务。

正式独立测试应按纠纷分组，在family和阶段上覆盖本轮实际主张。规则库、文本编码、输入生成、mask政策和模型选择全部先锁定，再打开测试参考。测试结果不好时，不修改方法后继续把同一批当作首次测试。

跨family泛化是后续更强的实验，不是本轮开工条件。到时必须把留出family的规则文字作为已给定知识，并禁止使用其案件目标调模板，才能区分“能读新规则”与“已见过该family的答案”。

## 八、实现上只保留一套主干，不再每轮叠一层新脚本

建议在现有代码上形成下列稳定接口；最新本地native模块应先检查后复用，而不是因为远端暂不可读就重写一套。

| 模块 | 明确职责 |
|---|---|
| `corpus_inventory` | 候选发现、family／版本标识、纠纷分组、暴露记录 |
| `rule_templates` | 法源与条件模板；不承诺全案完整 |
| `input_partition` | 来源跨度、阶段、实体与依赖处理；不读监督类别 |
| `target_adapter` | 裁判条件目标、`basis_kind`、监督mask |
| `graph_builder` | 只接收输入；候选连接与有来源关系分开 |
| `text_cache` | 冻结文本编码，所有模型复用 |
| `application_models` | 条件先验、Flat、R-GCN |
| `train_eval` | 分组划分、masked loss、训练、预测与统一评价 |

原始文件继续不可变，但派生数据可以有版本。**不可变的是历史事实和已报告实验；不是说开发阶段永远不能修正通用实现。**

同样，和组内对齐应通过“canonical输入适配到上述接口”完成。拿不到真实产物时保留接口状态，不宣称已集成；拿到之后跑同一套构建器。Pattern mining以后可以作为新增输入或对照，但现在无需你先实现FP-Growth、gSpan和AMIE，才能开始GNN训练。

---

**这套方案的核心变化，是让训练任务与我们真正拥有的监督粒度匹配。** 不再要求一个案件给出完整、无争议、所有条件齐备的法律证明，才允许任何模型学习；也不把没被法院裁判的事项伪装成已知“未决”答案。

下一轮的交付应该同时包含：**一批有部分监督的真实输入、已经运行的Flat／GNN训练代码，以及一次完整的分组开发比较。** 数据数量影响结论力度，但不再成为所有工程工作的统一停工按钮。这样才真正开始研究“关系结构有没有帮助法律适用”，而不是继续研究“怎样让整案通过我们自己越来越严格的验收”。
