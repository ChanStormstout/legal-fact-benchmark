三、资料覆盖：建立“可核验缺口”，不要把模型答不出直接叫作缺法源
1. 以法律子问题为单位记录，不以整案为单位贴标签

我建议每个案件只整理实际存在的子问题，例如“遗嘱导致的转移如何评价”“某许可覆盖哪个主体与对象”“特定法条的时间条件是否相关”。子问题必须由允许案情、明确争点、当事人提出的路线或已提供的下级法院判断触发。

每个子问题保留下列状态：

事实信息缺口：判断需要某个日期、对象、控制关系或文书内容，但允许材料没有提供。
库内法律依据缺口：完成对当前相关来源的原文检查后，尚未取得足以支持该法律命题的材料。
来源取得／范围确认缺口：找到了引文、摘要或候选判例，但原文、法院采纳状态、适用范围或依赖上下文尚未确认。
送达缺口或使用失败：依据已经在库，进一步区分预算未送达与送达后误用。

这里的“库内法律依据缺口”只能表述为：

在本轮已检查的来源及指定范围内，尚未取得支持该命题的可核验依据。

它不等于“法律没有规定”，也不等于“没有适用先例”。

2. 如何区分“模型不懂”和“确实没有取得资料”

采取一个有限的检查顺序：

先定位命题，再查原文，再判断能否支持，最后检查送达与使用。

例如，模型遗漏遗嘱路线时，首先检查允许输入中是否存在该事实和争辩；存在，就能够确认“识别该路线不需要新增材料”。至于这条路线的法律效果，再单独检查库内法源，不能把前一个问题的答案当成后一个问题的答案。

对于14项的小库，可以做一次逐项原文审阅，而不必依赖检索排名来推断“有没有”。但审阅仍须允许 UNKNOWN：模型找不到支持段落，可能来自材料不足、上下文不完整，也可能来自审阅错误。

**缺口判定至少应保存：待支持的具体命题、检查过的来源、找到的最接近原文、为何仍不足。**只有“模型说缺资料”这一句话，不应进入实验标签。

3. 当事人引用，不自动升级为法院规则

每条提取规则都要保存一个简短的“采纳记录”：

项目	需要明确什么
陈述者	当事人、被引用判决、当前来源法院，还是编辑性摘要
陈述位置	诉辩摘要、证据叙述、法院分析、结论或附带讨论
法院处理	明确采纳、拒绝、区分、保留、仅转述、无法确定
命题范围	谁、何种对象、何种行为、什么时间和程序条件
限定	例外、否定、程度词、依赖的其他段落或法条

不能只截出“某判例认为……”后的一句。如果接下来的段落是“该案不适用于当前情形”，这个区分理由属于必要上下文。

也不要强迫模型给所有句子贴上确定的“判决理由／附带意见”标签。证据不足时，保存“法院陈述，但在该裁判中的作用未确认”更稳妥。

CLERC 的原文分析也展示了一个相关风险：**引用到了正确案件，生成的命题仍可能不受该案件支持。**因此，“命中文书”和“命题得到支持”需要分别检查。

每份候选依次经过五个状态：

候选发现 → 原文取得 → 命题提取 → 采纳与范围确认 → 条件化应用。

前一步完成，不自动代表后一步完成。尤其是“原文取得”与“直接适用”之间，需要保留明确的范围判断。

停止条件设为：

找到能够支持基础命题并说明已发现重要限定的原文组合，或者达到查询／原文数量上限，本轮即停止。

达到上限仍不够，就保留缺口。没有搜到反对依据，也只能记录“本轮未取得”，不能写成“没有反对依据”。

2. 推荐的模式发现路径

我推荐把当前机制假说调整为：

有来源的法律条件帮助确定值得保留的关系结构；历史材料中的重复结构再帮助新案提出和定位法律子问题。

这保留了原来的最终目标，但改变了当前可主张的发现方式。你们暂时研究的是法源约束下的结构发现与使用，不能称作“完全无先验地发现法律规则”。

具体做法是：

**第一步，先提取来源明确表达的规则及条件。**保留“可能”“通常”“除非”等程度与例外，不能把条件性陈述硬化成充分必要条件。

**第二步，找哪些条件需要关系绑定。**例如，“占用的是哪处房产”“控制保留在谁手中”“同意针对哪份租约、哪个受让主体”。只有需要区分这些绑定的法律问题，才可能体现关系结构相对于普通关键词的价值。

**第三步，再到允许历史材料中寻找重复结构。**起步仍可保持至多两个记录、一个直接关系条件的限制，避免借口“更法律相关”无限扩张搜索空间。已有词表无法表示的事实应标为表示缺口，不应悄悄由模型补成已存在事件。

**第四步，把模式输出限制为检索动作。**例如触发“第三方使用与控制转移的区分”这一法律问题，或指出需要检查许可对象范围。模式匹配本身不输出腾退成立。

3. 三种对象必须始终分开

事实关系图保存某个案件中谁说了什么、涉及哪个对象、有哪些明确关系。

Pattern是在多个案件图中重复出现的带变量查询；每次匹配都有具体事件、对象与原文见证。

法律规则是有规范性效果的来源命题，或者尚待验证的跨案归纳候选。事实结构重复，不能自行授予它法律效力。

R-GCN 的隐向量还属于第四种东西：即使网络利用了某种邻接结构，也不能直接把隐藏表示称为发现了可解释 pattern 或法律规则。

4. Rule extraction 与 induction 的主张变化

本阶段优先做 rule extraction：从法源原文提取条件、效果、范围与限定。

Rule induction 暂缓成为主结论。跨案出现某种结构并伴随某种结果，仍需检查反例、事实遗漏、法域差异、程序阶段与选择偏差。当前20份开发文书和稀疏匹配不能承担这些要求。

LegalSearchLM 的要件导向检索支持“围绕法律问题组织表示”这条研究方向，但其方法使用模型提取要件并进行生成式检索训练；其相关性定义来自韩国刑事案件体系，部分数据构造还纳入推理与结论。不能直接搬入你们排除目标终局的输入协议。

+1

**Pattern 阶段的停止条件：**若固定候选中找不到既有跨纠纷重复见证、又对应明确法律检索问题的结构，就报告“当前表示下尚未发现有此用途的候选”，停止增加模式数量。程序连接工具依然可以保留，但不再把它包装成论文核心。

七、R-GCN 的具体方案：微型关系编码器，只学习法源排序
1. 14项法源与六案，究竟够不够？

足够做接口、结构敏感性和受限开发训练；不足以据此宣称稳定泛化或神经方法优越。

关键限制主要在查询与监督。六案×14候选形成84个案件—来源位置，但它们并非84个独立法律任务；同一案件中的候选高度相关。277条事件、更多图边、更多 pattern 匹配，也不会自动变成更多法源排序监督。

真正可学习的问题至少需要出现：

针对给定争点，来源甲有可核验用途，来源乙经检查没有对应用途；并且这种相对优先关系随案件或争点发生变化。

若所有监督都只是“DRC16 在所有案件都应靠前”，学习一个固定优先级就够了，无法证明需要案件关系图。

2. 监督分三层保存，本轮只训练排序
层面	记录内容	本轮用途
主题关系	是否涉及当前法律子问题	输入匹配与审阅
范围兼容	可直接适用、仅类比、明确不相容、未知	共同过滤／标记，不能与要件满足混同
有用性	能提供基础规则、反论、限定、依赖，或经检查不响应问题	形成有限排序监督

一个反对用户立场的判例可以非常有用。未被引用、未被旧参考列出、尚未审阅的来源，均不能自动充当负例。

还要区分“单份来源有用”与“在已经选了若干来源之后还有多少新增价值”。后者涉及材料互补与预算，主要由装包器处理，不应期望一个独立相关性分数完整解决。

3. 推荐的最小图

采用五类节点，全部可落在小型表结构中：

节点	内容
I：争点节点	允许材料产生的法律子问题与中性描述
F：事实／断言节点	事件类型、陈述者、主张／认定、法院层级、阶段、否定、时间及未知字段
O：对象节点	当事人、群体、房产、合同等；保留类型与未解析状态
R：规则／条件节点	来源原文中的命题、条件、限定、例外；区分子类型
D：法源节点	原14项来源及可核验元数据、必要依赖

事实侧关系包括 asserted_by、actor、property、contract，以及已有的有方向 part_of、member_of。规则侧关系包括 contains、requires、exception_to、qualifies、depends_on。

每条事实边仍保留原文出处。缺少一条关系只说明当前图没有可用证据，不能编码成“关系确定不存在”。附件原有的不自动传递、不继承群体行为、不把部分与整体视为相同对象等语义边界全部保留。
粘贴的文本 (1)

特别需要强调：神经消息沿 member_of 传播，不代表个人继承群体的法律行为；向量传播没有法律推导效力。

4. 新案件推理时，哪些东西可以进入图？

可以进入的是：新案允许事实、原文可见主体与对象关系、预先取得法源中的规则结构、允许使用的时间与法域信息。

不能进入的是：

参考答案中的“本案正确法源”链接；
目标终局或决定性最终分析；
由目标结论反推出的“条件已满足”边；
测试案件的有用性标签及其反向边。

来源D包含规则R 可以作为输入；案件Q应使用来源D 是待预测关系，不能预先加入。

**时间与范围限制必须在消息传播前生效。**只在输出时屏蔽晚出法源还不够：其信息可能已经通过图邻居传播进其他来源。对明确禁止进入该案件输入的来源及其派生节点，要先从案件对应的图视图移除。范围未知则保留未知标记，不能擅自当作不相容。

5. 初始特征与模型结构

本轮不新增预训练文本编码器。使用现有词项处理产生的固定维度文本特征、节点类型、已知／未知掩码、断言状态、必要的范围元数据；不使用可训练案件ID、结果标签或“正确来源ID”。

推荐固定配置：

两层 R-GCN，隐藏维度16，两个关系基矩阵，共享关系参数；总可训练参数上限5万；两颗固定随机种子；不做超参数搜索。

2. 怎样获得监督，避免把模型意见重新命名为 gold？

法源规则卡采用“只看来源”的提取；案件事实卡采用“只看允许案情”的提取。之后另开审阅任务，给出案件与原文来源，形成有用性及有限优先关系。审阅时不展示 A/B/C 排名，也不展示它们的回答。

每一条明确标签必须附原文位置与理由。复核冲突保留为未知，不要求第二个回答强行裁决第一个。

所有这些标签统称：

模型辅助、原文可追溯的有限参考。

新对话不会消除同模型的共同偏差；特征提取和标签判断也可能共享误解。网页模型还可能已有判决记忆，输入隔离无法证明其预训练中从未见过相关案件。

3. 什么时候启动训练？

我不建议给出一个“满多少条便足够科学有效”的虚假门槛。这里的门槛只负责判断是否值得启动这个小诊断：

有跨纠纷来源的明确偏序，且不限于把一个固定法源整体上调；
留出案件之外的训练部分仍存在正向用途与经核验的不响应候选；
能用原文说明偏序，未知候选无需被迫转为负例；
输入特征中没有待预测的正确法源链接。

不满足时，本轮停在结构匹配、来源覆盖与接口检查。允许测试输入输出、关系方向、预算闭包；随机初始化网络给出分数，不构成 R-GCN 效果验证。

6. 评价顺序与晋级条件

评价必须依次穿过四关：

**第一关：工程与语义边界。**来源引用能解析，未知没有被当作否定，主体与阶段未被合并，没有泄漏、预算超限或依赖断裂。

**第二关：有限排序。**报告已确认来源的实际排名，以及已审阅偏序的满足比例。未知候选不能按不相关计算完整 NDCG 或“准确率”。

**第三关：实际送达。**检查选中原文及完整输入是否改变；按案报告新增规则、丢失依据、反论／限定保留情况。若最终材料逐字相同，停止进入回答比较。

**第四关：是否值得保留 C。**建议预先规定一个工程晋级标准：两颗种子均优于 B 的有限排序表现，且至少两个纠纷组出现已确认有用依据的实际新增送达，没有丢失某活跃争点最后一份已确认的重要反论／限定；C₀ 不能完整复现该收益。

这个标准是投入决策线，既不是显著性检验，也不是法律正确保证。

若 C 只提高训练分数、只在一颗种子上获益、收益完全来自固定法名优先，或者优势没有转化为材料差异，**结束这一轮 R-GCN，不继续加层、加图边和反复调参。**保留 B 或转向装包问题。

十、贯穿例子：关系结构怎样帮助找法，又怎样避免直接推出结论

下面是明确假设的教学例子，其中规则 R_H 不代表已经核验的 DRC 法律命题。

假设两个历史案件 H1、H2 的允许材料都包含：

第三人 U 使用商铺 S；承租人 T 主张仍对商铺 S 保留控制。

一份已经核读的假设来源 D_H 明确表达：

在法域 J、时间范围 V 下，第三人使用房屋本身不足以完成某项法律判断，还需考察承租人对同一租赁标的的控制情况。

从历史材料到候选 pattern

历史事实图分别保存两个断言：

断言	角色与对象	陈述状态
USE_PROPERTY	user=U，property=S	按各自原文保存
RETAIN_CONTROL	controller=T，property=S	PARTY_CLAIMED

候选 pattern 是两个断言通过同一房产对象连接。它提示应寻找“使用与控制的区分”这一法律问题。

如果第二个断言实际针对另一商铺 S′，即便文字都出现“商铺、使用、控制”，这个具体绑定就不成立。如果原文只说明 S 是建筑 B 的一部分，也不能自动把对 B 的任何许可解释为对 S 上某项交易的同意。

新案的图如何形成

新案 Q 的允许材料写道：房东认为 U 独占 S，承租人反驳自己仍保留钥匙与进入权。可形成如下边：

起点	关系	终点

一个合格的条件化回答应类似：

在假设规则 R_H 的范围已经确认适用的前提下，现有关于第三人使用的材料需要与控制情况一并分析。房东主张独占，承租人提出保留控制的反论；应分别说明各自证据及已有法院判断。若决定性的控制事实或许可范围仍未确定，应保留该分支的不确定性。

这里，pattern 帮助定位了该查什么法、该保留哪些对立材料；它没有把 PARTY_CLAIMED 转成 COURT_FOUND，也没有直接完成法律结论。

十一、最终执行路线与改变建议的条件

建议把路线固定为：

允许事实与争点 → 小型来源对齐表 → 区分库外缺口和库内选择机会 → 固定库 A/B/C 排序与送达诊断 → 有收益后比较最终分析 → 再单独检验显式 pattern 的增量。

有界补查负责建立下一版来源库；当前提示试验负责已送达材料的使用。它们各有作用，但不混入这一次图排序处理。

观察结果	下一步决定
独立法律路线没有取得必要依据	对该缺口做有界补查；不让图排序冒充补法
有足够依据，但不同排名没有改变最终材料	优先检查预算和依赖装包，暂停新增回答
B 改善，C 没有额外改善	保留 B，停止本轮 R-GCN 调参
C 改善，但 C₀ 同样改善	不能归因于消息传播，优先较简单实现
C 稳定改善实际送达且保住重要限定	冻结选择方法，再做两条件最终回答比较
更好的材料送达后仍被误用	回到主体／阶段／反论／条件应用检查
没有法律问题明确、跨纠纷可匹配的候选 pattern	保留关系连接功能，收缩 pattern 主张，不继续靠增加数量制造进展

之后真正测试 pattern 时，只需先做一个两条件比较：**同一事实图、同一来源库、同一排序器与预算，加入或不加入冻结的显式 pattern 特征。**若 pattern 导致额外库外发现，须另列“新增信息”效果，不能与“同信息下的结构使用”混算。最后才看它是否改善法律分析。

这条路线保留了原项目“历史事实结构和有出处规则帮助新案找法与分析”的目标，也允许现在开始有限的图学习尝试。它要求每个组件证明自己改变了哪一个下游决策；证明不了，就停在相应证据层级，而不通过扩充组件或改写研究主张来掩盖。
