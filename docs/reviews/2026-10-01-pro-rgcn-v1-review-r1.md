# GPT Pro 双 R-GCN 方案评审与实施顺序

日期：2026-10-01。性质：设计评审和待实施建议，不是已冻结的方法或新实验结果。对照代码起点为 `31d9813649b67b1796afd26518845ba6b82848d5`，分支为 `research/rules-and-verdict`。被评审的用户附件 SHA-256：`13c90c254319c14853659ec2e4bdf61f7582d3be57b524acd7675acc62080cbc`。

## 判断

方案的整体方向与当前目标相符：把案件事实、争点、法律条件和法源连接起来，分别评价找法和逐请求结果判断。来源追踪、对象绑定、陈述状态、未知处理、法源版本、候选召回失败、折外检索和同信息基线等设计均应保留。它已经给出两个图模型的输入、监督和损失，不能说只是画了两个 GNN 方框。

但不宜整套作为第一版同时实现。主要缺口是：跨案件的法律规则归纳尚未成为独立算法；现有关系诊断数据不能直接训练两个法律任务；图网络不能保证规则逻辑成立；更换为 35B 模型和 vLLM 缺少本机验证。建议先完成可审查的“历史案件归纳候选规则 → 找法 → 逐项应用 → 请求结论”，再分别决定是否引入 LawRanker 和 VerdictNet。

本次没有修改算法、模型配置、标注或历史结果，没有启动模型、下载模型或训练图网络。尚未完成的 `local_chunk_v11.py` 不纳入本次设计或发布。

## 当前代码和结果能支持什么

`field_pipeline_v2.py` 已有带出处的已知字段、字段级限制、类型优先筛选、绑定见证和未知候选。`typed_relations.py` 支持明确方向的 `part_of` 和 `member_of`；缺边保留未知，身份相同不能替代这两种关系。`scoped_mining.py` 实现有预算的双事件模式搜索。它们可以复用，但还不是支持任意 AND／OR、量词、例外优先级、举证责任和金额计算的法律规则引擎。

最新完整同配置 A/B 开发比较是 v3：8 案、13 题，相对模型参考答案，5 道正例均未识别，其中 B 一题对应的生成截断。v10 是额外调用的两案诊断，两个 MATCH 中一个受原文支持，一个不受支持。123036 案中，房东自用需要被抽成转租；关系边即使正确，程序仍会基于错误事实匹配。这说明当前至少同时存在语义抽取和群体表示问题，不能假定输入图已可靠，也不能从这两案估计整体错误率。见 [v3 报告](../../outputs/local-qwen-pattern-eval-v3/report-zh.txt)、[v10 报告](../../outputs/local-qwen-pattern-eval-v10/report-zh.txt)。

## 各组件评估

| 组件 | 合理之处 | V1 应补的内容与处理 |
| --- | --- | --- |
| 案件＋请求＋阶段 | 避免把一案多请求、多次上诉压成一个胜败 | 固定预测的是当前请求的哪项处置。实体、程序、发回和部分支持分开；某争点只有二元结论时，不强凑三分类。历史裁判一致性与法律判断正确性分开评价。 |
| 输入隔离 | 已明确目标理由、结论和最终引文不能泄漏 | 检查派生摘要、法院采纳状态、节点文本、文件名和嵌入也来自允许输入；历史训练案件的完整推理可以使用，目标案件不可混入。使用事后整理事实时，只称条件性法律适用实验。 |
| 固定 LLM＋结构约束 | 抽取与预测分离；JSON Schema 解决可读取问题 | 沿用现有 9B＋MLX 起点。35B 是单独的模型迁移候选，不能与架构改动一起静默更换。结构正确不证明语义正确；允许 OTHER、空结果和未知，避免把所有片段强制抽成目标类型。 |
| 分段抽取与局部核查 | 有限调用，能处理全文 | 4,000／400 tokens 不解决跨段身份。增加案件内对象登记、出处支持的别名对应、重叠片段去重和指代未决记录；同角色不合并，同段重复不是新事件。只补相关上下文，不能用含答案的整案摘要。 |
| DefinitionCard 定义映射 | 比先做全库两两合并更易控制；保留实例 | 定义卡不是完整性证明。保存候选定义歧义、未映射事实与必保留限定。任何依据训练答案修订的定义都属于学习产物，必须受数据划分约束。 |
| 关系模式搜索 | 变量连接可复用，原始事实和低频例外仍可进入下游 | 作为描述性结构保留，不称法律规则。先用已有双事件实现；扩到 2–4 原子前明确允许操作、全局预算、扩展顺序和未搜索部分。按已确认纠纷组计数，关联不明不能称独立。不能把未知计成不匹配后做不安全剪枝。 |
| 法源库与 RuleCard | 版本、辖区、定义、例外、必要与充分条件区分正确 | 补充引用的作用：被采纳、被区分、被否定、只被引述等。明确规则出自法条还是从案例归纳；原文法源与可错的机器解释分别保存。我们没有人工标注者，使用模型生成并依据原文复核的状态。 |
| BM25＋向量＋RRF＋文本重排 | 原文和结构查询并行可缓解抽取遗漏；可作为强基线 | 固定实际可用语料、版本、向量模型和重排输入。候选 200→40→8 每步分别记录已确认相关法源的保留率。20／20 配额和 top-8 是待开发检查的预算，不是法律完整性保证。必要依赖超预算应明确未完成。 |
| LawRanker | 区分关系类型并按争点排序，有研究依据 | 延后到“法源已召回但排序差”可定位、监督可用时。先比较相同候选和节点信息的文本重排、无图 MLP、R-GCN。它学的是相关性，不证明法律有效或条件满足。 |
| 条件执行＋语义判断 | 最能直接体现对象连接、状态和例外的用途 | 尽早实现少量实际条件。保存量词、变量绑定、组合逻辑、例外作用点和材料范围；只执行已有语义的操作。支持／反对证据可同时存在，不能只用单条置信度代替。开放判断保留解释，不装成确定计算。 |
| VerdictNet | 与找法独立训练便于定位错误；保留原始预测是正确的 | 当前不作为 V1 必选最终决策器。先测同一条件表交给固定 LLM、简单分类器或适用的纯执行器；再检验消息传递是否有额外收益。GNN＋事后解释不保证解释忠实反映模型决策。 |
| 有限反馈控制器 | 区分缺法、缺事实和解释争议；有停止预算 | 先跑零反馈，再增加一次明确缺口补查。检索应同时考虑支持与反对候选；每次补查记录改变了哪个条件及结果，不能只围绕初始 verdict 寻找支持。 |
| 监督、折外检索与评测 | U 不当负例、候选遗漏计失败、训练输入含真实噪声、同信息消融均正确 | 不只是 LawRanker：归纳规则、学习到的定义、模式和阈值也必须在对应训练折内形成。五折及三随机种子依赖实际纠纷数与标签覆盖，不能机械执行。未判断的检索候选不能在指标中偷偷按不相关计分。 |

## 最关键的补充：明确“从案件学到什么规则”

方案当前有事实模式搜索和从法源抽取 RuleCard，但没有完整说明如何从多个历史案件得到可复用的法律判断条件。两个 GNN 的权重也不能直接替代可检查的规则。

建议保留三种有明确来源的记录：描述性事实模式；法源明文规则；案例归纳的候选规则。第三种规则必须保存适用争点、法域／时间／阶段、条件及变量、法律后果或因素作用、例外、支持与反对案件、法院理由出处、对应法源和未决解释。若只观察到结果关联，应标记为经验关联，不能升级为有法律效力的规则。

开发期按同一争点、法律版本和阶段组织已有案例。LLM 从法院理由提出少量候选条件，程序保留实例绑定；再用同一开发范围内的相近案件检查是否过度泛化、是否遗漏例外。只进行预先限制的一次局部修订，然后冻结并检查其他案件。支持数仅说明重复观察，不能以多数投票决定法律效力。

举一个纯算法例子，不陈述真实印度法：历史理由反复强调“债务与通知必须对应同一租约”。系统应把这个共享变量条件连回提出该要求的法源。新案中的欠款属于 K1，而通知属于 K2，便不能用这份通知支持该条件；还必须检查其他通知，不能据此认定整案一定败诉。研究要证明这一连接在新案中有用，而不只是程序能执行一条人为给定的查询。

这种归纳可借鉴 [LRI／SILVER（2025）第 3.3 节](https://arxiv.org/html/2505.14104v2)：提出规则、逐案例检查、补充覆盖。该工作的多数支持标准不能直接充当我们的合法性标准，其设定也未完整覆盖可被例外推翻的复杂规则。[RLJP（2025）第 3.4 节](https://arxiv.org/html/2505.21281v1)提供相似事实但不同结果的反例选择思路；我们应把实际法院理由作为约束，不能仅为提高开发结果分数修改法律条件。

## 两个 R-GCN 应怎样定位

R-GCN 是沿不同类型的边传递信息的图神经网络。提案中的 basis 参数共享是现成机制，争点门控则根据当前 issue 调整各类边的权重。这个选择可以试验；三层、256 维、4 个 basis 属于初始化配置，尚没有本项目证据证明最合适。[原始 R-GCN 方法](https://arxiv.org/html/1703.06103v4)

门控 `g_r(q)` 对同一争点下同一种关系使用同一个系数；这个门控本身不会区分两条具体边的重要性，区别还依赖节点内容和后续聚合。若首轮只有一个近乎固定的争点，门控可能退化成近乎固定权重，不能用该实验宣称已证明跨争点调节能力。三层是否足够也取决于实际图中的路径及读出方式，先查看关键条件的信息经过几条边，不盲目加深网络。

图上同时连接 A、B、C 并不明确表示 `A AND (B OR C)`。规则卡和执行记录需要显式保存组合逻辑以及每组变量绑定；图网络可学习如何利用这些信息，但软分数不能替代必要条件检查。同一断言出现在来源节点、事实节点和多个模式实例中，还要避免把这种重复编码解释为多份独立证据。

两模型分开训练是合理设计，同架构则不是必要条件。优先验证 LawRanker：它的错误可定位到具体候选法源。VerdictNet 只有在条件表、请求标签、不同结果和足够多未重复纠纷可用后，才适合开展有意义的学习曲线。现有 6,954 条原始记录或 20 案关系抽取，均不能直接当作这么多已准备好的监督样本；也不存在未经试验就能保证“达到某个案件数足够”的阈值。

近期依据也有边界：[GFM-RAG（2025）](https://arxiv.org/html/2502.01113v3)使用查询相关图传播，但经过大规模知识图和检索监督训练；不能将其结果直接转移给小样本随机初始化 R-GCN。[UniLR（ACL 2025）第 3 节](https://aclanthology.org/2025.acl-long.584.pdf)将法律要素监督、图结构和检索学习结合，提供更接近找法的对照；其带标签的图构造必须在我们的目标案件上严格检查信息可见性。

## 运行环境与抽取前提

沿用现有 `mlx-community/Qwen3.5-9B-4bit`、固定 revision 和项目专用 MLX 环境，能够先隔离方法变化。它的语义能力尚未验证充分，不能因为已有环境就假定它一定胜任。若决定比较更大抽取模型，另开有限的资源与抽取检查，只在已有开发材料上做，之后冻结模型再比较架构。

35B-A3B 的官方说明是总参数 35B、激活参数 3B。激活参数少不等于只需储存 3B 权重。仅按全部 35B 权重 4-bit 理想估算就是 17.5 GB，尚未加量化开销、更高精度部分、缓存、运行时和系统内存；因此不能承诺 24 GB 机器上的长上下文配置可行。该估算也不是实测结论。[官方模型卡](https://huggingface.co/Qwen/Qwen3.5-35B-A3B)

vLLM 当前文档列有通过 vLLM-Metal 使用 Apple Silicon，不能笼统说它不支持 Mac；但平台插件可用不等于特定模型、量化格式和结构输出组合已验证。[安装文档](https://docs.vllm.ai/en/latest/getting_started/installation/)。[JSON Schema 支持](https://docs.vllm.ai/en/latest/features/structured_outputs/)是可取的输出约束，项目已有 MLX 约束路径，没有必要仅为相同功能迁移运行时。

Qwen3-Embedding-0.6B 支持最高 1024 维，选型在规格上成立。Embedding 和 reranker 应分阶段加载并缓存结果，避免与生成模型争用内存。重排采用完整、有界的法源单元，显式记录长度，不能照抄示例中的截断而丢掉定义或例外。[Embedding 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[Reranker 模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)

## 我建议的实施和实验顺序

先限定一个材料足够的实体争点。转租可能是候选，但现有三个对象关系问题不能自动升级成“转租是否足以腾退”。应先从已有材料确认具体法规、必要条件和目标阶段。这里建议先用约 5 个旧开发案例串起流程；不是重新抽取全部旧案件。随后固定选取一个小的新案件批次，例如最多 10 案，选择规则先写定，不能因方法失败换案。

| 顺序 | 实现／保存 | 比较和继续条件 |
| --- | --- | --- |
| 1：任务与来源 | 输入可见性、请求级结果、真实法源及版本、少量必要条件；复用旧来源和有效记录 | 能对具体请求解释“输入是什么、参考依据是什么”。若来源只有上诉程序结果，就分开报告，不造实体标签。 |
| 2：最小端到端链 | 法源检索、少量 RuleCard、已有字段与关系执行、条件表、固定 LLM 结论；有限规则归纳单独保存 | 跑固定模型的原文直接回答、文本 RAG 和结构化条件方法。保留全部失败；不等全量事实核查或训练 GNN。 |
| 3：检验案例规则的新增作用 | 在相同历史案例和法源范围内，加入已冻结的案例归纳规则 | 对照“只有法条规则”“检索历史理由原文”“归纳规则卡”；判断规则抽象是否比额外提供历史知识本身更有用。 |
| 4：隔离表示与模式作用 | 相同事实、相同法源和相同条件记录，保留／去掉重复模式；关系约束与共现对照 | 模式是派生信息，比较时保留其组成事实，避免删除模式同时删掉证据。共现多出的候选必须对原文检查，不能全部算错误。 |
| 5：按错误选择学习模块 | 若正确法源已在池中但排序差，先训练 LawRanker；若条件记录充分而结果组合仍差，再试 VerdictNet | 文本重排／无图 MLP／R-GCN 使用同一候选、向量和监督；VerdictNet 对比同条件表的 LLM、MLP及适用的纯执行器。训练样本不足时报告，不用随机图网络充数。 |
| 6：检查补查收益 | 在已经跑通的固定版本上，增加最多一次缺口驱动补查 | 同预算文本 RAG 也可多检索一次。分别记录补到了什么、是否纠正错误及新增成本，再决定是否增加轮数。 |

第 2 步的新模块以 `prepare_legal_task`、`index_authorities`、`retrieve_authorities`、`build_rule_cards`、`assess_conditions`、`decide_claim` 和 `evaluate_legal_task` 为职责边界；这些是建议名称，尚未创建。关系执行复用现有模块，经适配输出条件表。案例归纳另外保存 `induce_case_rules` 的候选、反例与版本，避免和法条抽取混为一谈。图张量继续由可阅读的记录生成，暂不让图框架成为第一批模块的依赖。

首轮条件判断使用已支持的身份、明确关系和已知时间操作；新增条件的操作语义要单独说明。不能直接把当前执行器返回 NOT_FOUND 翻译为“法律条件被推翻”。只有明确反证才能形成反对依据；材料内找不到和关键事实未知分别保留。

## 实验必须回答的因果问题

主比较先控制受测模型、允许材料、历史案例库、法源范围和预算。原文直接回答判断模型基础能力；文本 RAG 检查提供法源的作用；相同法源下加入对象绑定和条件表，检验结构化应用；再加入从同一历史材料归纳的规则，检验规则复用。提案已有的强 RAG、序列化 LLM、MLP、去模式消融都应保留，区别在于按顺序实施，而不是一次训练全部组件。

另设两个诊断输入：来源复核后的关键事实，以及来源复核后的适用法源。它们用于定位抽取错误还是找法／应用错误，必须与受测模型自行抽取的端到端结果分列。不能因为诊断组成功，就认为自动流程成功。

结果按请求单位保留，至少检查：已确认相关法源是否进入候选和最终列表；所需条件是否正确绑定；结论是否与历史结果或明确任务参考一致；支持结论的决定性依据是否成立；未知、技术失败、拒答覆盖和成本。某些题没有独立的完整相关法源清单时，只报告已核验法源的覆盖和固定抽查，不声称穷尽召回率。未核验候选标为 U，不能当负例来计算漂亮的排序指标。

最终 verdict 一致不能替代依据正确。反过来，部分条件缺失也不自动意味着算法应弃答：如果适用的举证责任规则已经明确这种证明状态如何影响结果，可以依法源作出任务范围内的判断；该程序规则必须显式存在。模型拒答与历史结果标签分开保存，技术失败则不给实质答案。

训练／开发／检查按已确认纠纷组隔离，关联未知单列；历史回测还要满足法源和先例的可用时间。折外生成必须覆盖所有根据答案形成的规则、模式和映射；单个固定公开法条不必因折数复制语义，但其学习到的抽取／筛选版本需要受同样边界约束。新题暴露后修改了方法，就转为开发材料。

参考仍由普通 High 网页模型生成并依据原文复核，不要求人工标注者，不称人工金标准。小规模先给逐题结果和来源支持，不把同案多条事实当独立样本，也不以未知减少、匹配增加或程序测试数替代方法准确性。
