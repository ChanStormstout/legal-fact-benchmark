# 真实判决推理重建 v2

本阶段以 Student Implementation Guide 4.0 指定的三份教学判决为材料，研究完整判决中的推理重建。模型可以读取最终理由；最终处分仅用于对照，不能作为推导自身的前提。本阶段结果不得写成判前预测、独立法律测试或法律认证。

## 实际接口与信息流

准备阶段调用 `prepare_sources()`，复用文书响应边界解析，分别恢复三份完整正文。每段保留真实文书 ID、URL、原始响应的字符及字节位置、行号；`tasks/*/delivery.json` 记录正文到实际任务的映射。来源是公共判决的网页呈现，不是经认证的法院副本；判决提到的证据原件没有独立取得。被引先例仅以目标判决的转述进入本轮。

每案最多五次普通 High 独立临时对话，按规则草案、规则来源复核、事实提议、独立来源参考、推导提议提交。独立参考只看到完整原文与统一任务合同，不读取规则草案、事实提议、检查结果或旧答案。最初冻结保留在 `freeze/config.json`；首次真实凭据执行前，分别修订范围元数据接口和参考隔离接口，新快照在 `freeze/interface-01` 与 `freeze/interface-02`。实际英语合同位于 `realcase_tasks_v2_2.py`，运行入口为 `scripts/proof_realcase_v2_2.py`。除独立参考移除可能带有本案分析的规则草案外，其余任务文字未变；已有兼容生成直接复用，不重答。动态任务逐次记录真实附件哈希。无付费 API、Pro、本地推理或语义重试。

规则草案明确结论类型、输入命题类型、必要对象角色、允许的陈述地位、时间要求、适用阶段、例外及未覆盖内容。ALL/ANY 只表达来源支持的充分推导。前件不成立不能自动推出结论为假；需要表达否定结论时，必须另有有依据的否定命题和规则。开放性法律评价保持 OPEN_TEXT，程序不把列举因素自动改写成充分 AND。

每项前提的状态与其来源地位分开。`TRUE` 可以表示“法院认定所有权未获证明”这项记录成立，不表示“当事人现实中没有所有权”。同一角色名称不能建立身份关系；共享角色的实际实体绑定和必要时间范围须一致。前提审阅决定按内容哈希绑定；模型参考和主线程来源审阅仍是模型辅助，不是具名法律批准。

推导提议的输入槽明确引用原始前提或先前步骤。`realcase_engine.py` 仅封装原始提议，不调用检查器的语义判定。独立进程 `scripts/check_realcase_certificate_v2_1.py` 加载固定快照和信任清单，自行检查来源字节、规则版本、命题类型、陈述地位、绑定、时间、依赖循环和有限组合。自由文字的法域与阶段描述通过另外保存、按内容哈希固定的研究范围审阅接入，不能与字符串 `India` 作简单相等比较。每个请求保存自己的结果；一条依赖不完整不会封锁其他请求。来源存在及引文可定位均不表示语义正确。

当前研究轨迹分为 `VALID_UNDER_ASSUMPTIONS`、`INCOMPLETE`、`INVALID`；技术失败的答案为 null。法律批准单列为 `APPROVAL_PENDING`，不改变已知命题状态，也不计入“成功拒绝错误推导”。本版本不生成法律批准意义上的 CHECKED。未来批准须作为新记录和新快照接入，不能倒改旧研究快照。

`INVALID` 表示提交的凭据与本版本可执行合同不相容，并不直接表示其自由文字法律结论为假。例如，模型将一个有来源支持、但程序标为 `OPEN_TEXT` 的判断提议为 TRUE，会触发结果不匹配；报告将它记为执行覆盖／状态接口问题，不能算作识别了错误法律结论。自动引文定位对呈现层标点空白也可能过严，原始失败保留，修正必须另建记录。

最终解释由确定性模板恢复，不再调用模型补写。模型的结论文字保留为提议，自动检查的是对应的类型化命题与依赖，不声称已自动核验自由文字含义。解释显示前提、反论、限制、出处、程序结果和批准状态。

## 评价安排

真实来源到凭据、同一缓存提议检查前后、图的审阅排序分别评价。先检查决定性事实、归属、规则翻译和范围，再统计有效推导保留、错误阻止、无依据结论及未完成原因。同案多条推导不是多个独立案件。构造错误与真实模型错误单列。

图使用提议中的正反关系和单位权重；逻辑依赖不转为支持票。来源顺序、简单未决连接及反对组合计数、简单分数加谱局部能量三种排序使用相同节点。度数按 P+N 计算；非唯一谱轴和孤立节点回退到简单排序；跨分量按节点数量分配前5/10名额。谱分数不改变事实、批准或凭据状态。三案只验证接口，不报告审阅效率提升或律师工时节约。

## 阶段边界与后续门槛

先完成三案教学交付和集中来源审阅，再决定校准数据准备。校准最多核读20个同家族候选，目标5案；完整试点30训练（含5校准）/10开发/20锁定测试仍是规划。旧租赁数据不自动迁入本家族，原SEALED不启封。四名标注者、合格法律审阅者、正式批准和锁定测试权限尚未落实，多个模型会话不能冒充这些人员。

每批冻结一次、运行一次、集中审阅一次。语义错误留在结果中，不逐案改提示追求成功。发现工程问题只能另存方法版本并明确受影响范围；不能混成同一冻结实验。全部历史结果、原始失败和冻结字节保留。本阶段只更新本地文档与审阅包，不提交推送。

工程验收使用真实入口、旧27场景和新链式依赖测试，覆盖来源字节、对象、时间、陈述地位、局部未知、AND/OR/例外、版本、空请求及保存不覆盖。测试通过只说明这些工程行为。

## 可复现入口

`proof_realcase_v2_2.py` 的 `task`、`ingest`、`snapshot` 和 `run` 操作在文件已存在时拒绝覆盖。历史结果直接读取；不要以重跑这些命令更新已完成快照。`scripts/proof_realcase_audit_v2.py` 通过实际独立检查器运行构造变异；`scripts/proof_realcase_revision_v2.py` 演示 Rame Gowda 的显式 S2 修正与历史 S1 重开。两者均不调用模型。

`scripts/render_realcase_walkthrough.py` 从保存记录生成可点击的来源到结论视图；`scripts/summarize_realcase_v2.py` 汇总实际提交、成本和检查前后表。两者不增加法律分析。网页精确型号、tokens、内部推理时间不可得；只保存 High、独立临时对话和观察区间，不能把观察区间解释为精确推理成本。
