# V20.4：引用已声明的局部编号

EV 是一个分析单元内 records 的位置编号，OBJ 是 objects 的位置编号，USE 是 uses 的位置编号。编号从 1 开始。旧 Schema 只限制字符串拼写和数组容量，没有把编号范围绑定到实际数组长度，因而允许只声明一个证据时枚举 EV:1–EV:256。

新字符约束器沿用 V20.3 共享来源表，另行跟踪已完整生成的声明数组。每个分析单元依次生成 analysis_status、records、objects、uses、judgments、limits；关闭声明数组后，才允许后续引用它的实际位置。引用范围分别隔离，不能借用其他单元的编号。已用完唯一数组内的可用编号时，不再允许逗号开启下一项，避免进入没有合法后续字符的状态。

对象角色字段继续允许 UNMAPPED；没有证据时 uses 必须为空，没有用途时 components 必须为空，判断的 uses 和 opposition_uses 可以为空。object_links 必须先选端点的 premise 再选该端点的 object，只允许存在对象的分析单元作为端点。所有端点都不存在时，不能开启关联项。这些限制不替模型补写证据、对象或用途。

生成后还有独立的完整 JSON 引用审计，按实际数组长度重新检查 EV、OBJ、USE，包括嵌套用途组合和跨单元对象关联。该审计不调用字符约束器。通过引用审计后，才恢复共享来源并交给原有 Schema、转换、独立处理检查和条件性计算。技术失败仍保存 null 正式答案，不用 UNKNOWN 代替失败。

缓存验收区分两件事：共享表示和字段顺序恢复后，所有数据值及数组顺序必须相同；实际存在的合法引用必须被接受，非法引用必须被拒绝。旧非法结果原样保存，不能通过猜测、删除或改编号使其通过。字段顺序会改变部分学习输入里序列化 JSON 的文本与哈希；验收解码对应 JSON 再比较数据，并单独记录字节是否相同。本轮没有训练或学习器的特征编码，不能把数据保真称为训练行为相同。

范围为一个已观察过的 TRAIN 任务 569555/P01，沿用同一 Qwen3.5-9B-4bit 快照、温度、种子、完整材料、规则、65,536 上下文和 16,384 输出上限，仅一次重跑。旧阶段已用时计入剩余预算，旧队列继续暂停。工程测试、合法引用与自然结束不证明证据语义、对象身份、来源相关性或法律结论正确。不得据此报告独立测试准确率或学习收益。
